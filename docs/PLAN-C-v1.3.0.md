# C 线 v1.3.0 修复方案（v3，三份同行评审后修订）

> 2026-10-29。v1.2.0 **不接受**。本版按三份评审重写，**评审确认前不开工**。
> 一句话：**C 的问题 90% 在数据，不在模型、不在轮数**；先修格框对位，再谈选优，最后才谈重训。

---

## 0. 先认三件事

1. **「一」的候选池本身是错位的，不是“选优选中了碎片”。**
   1,962 个标 `一` 的格随机抽 10 个，10 个都是“上一个字 + 底部一横”（即/甲/為/毎/心/科/君…），
   宽高比 0.60–1.88，真正的一应 >4。`cp=176.5`，字符实际高约 107，格框比字高。
   **任何在污染池上算的“同字中位/相对分辨率”都是错的**，所以顺序必须是
   `93 修格框对位 → 重切 → 绝对闸 → 相对闸`，不能倒。
2. **GAN 没错，它把错误目标学对了。**
   每格连通域数与文楷组件数之差：A 中位 +0 / 多≥2 占 **7%**；B +0 / **20%**；C **+1 / 33%**。
   A/B 有对照文本兜底，C 没有；双见证只验行文本，不验格内容。
3. **“只训 30 轮”是结果，不是原因。**
   207 页留出：ep20 **0.464** → ep30 0.444 → ep40 0.444 → ep50 **0.436**，ep20 后单调变差。
   A/B 到 ep60–80 才到顶；C 越训越记住错格。**修字源前不加训到 80 轮。**

## 2. 病因分层

### 2.1 切字/对位（一号根因，先修）

- `93` 的 y 窗口/`cp` 大于字符实际高度；字落在格下沿时，格把上一个字装进来；
- `一` 最极端（只有底部一横），1,962 个候选全错；
- `申/昌` 是局部错位；`一` 是格框高度问题；两字互换（`nc==nl`）不进入 37.4% 嫌疑集；
- 修法：**格框按墨迹实际 bbox 收紧**（y 向不触格边、不跨到上一字），`cp` 用实际字高/行内墨迹，
  而不是行距；重切后用**绝对几何**验（不依赖中位）。

### 2.2 选优

- 在污染池里选相对 medoid；`q`（Laplacian 方差）奖励毛边/碎边；
- 无绝对几何闸、无同类相对分辨率、无宽高比/组件数闸；
- 每字只取 1 个目标；`n<2` 226 字无法交叉校验。

### 2.3 生成

- 简体码位无真迹，GAN 目标全繁体 → 类/图/个 静默错形；
- 组件数守卫对偏旁级混淆失明（s2t 73% 差 ≤2）；
- ribbon 回退也要过逐字闸（图 回退后 4 组件→1）。

### 2.4 指标

- clean 参照自身 32.9% 在嫌疑行；崩坏率 14.1% 有近半可能是参照污染；
- Dice/chamfer 与自身样本比，共同缺陷被奖励；
- holes 不进选优、四/园 白名单；
- 像素 Dice 不能做三线投票（1,562 字误报 141，9%；一 比值 12.1），先看骨架。

## 3. 修复方案

### P0-0 反查 OCR（先做，2h 量级）

- 成品/候选字形渲染 → 单字 OCR（v6+v5）→ 读不回本字就报；
- **只在“双引擎都不一致”时进否决候选，单引擎不一致只降序/进人工桶**；
- 先在 **1,562 个三线皆真迹的可靠字**上跑，标定 FP（好格被误杀）与 FN（串→滿 能否抓到）；
  **FP >10% 则该工具只出复核清单，不许筛候选**；
- A/B 也跑，A/B 的“读不回率”作为该工具的 FP 基线；
- 产出 `work-c/reverse_ocr.json`。

### P0-0.6 几何自检（分钟级、零 OCR，先于 400 格）

- 每行格宽序列 `w[0..N-1]`：并格（`w > 1.4×行中位` 且下一个 `<0.6×`）、断格（`w <0.6×` 且相邻偏小）、CV >0.35；
- 全量 118 万格先扫一遍，输出 `work-c/geom_audit.json`：并格率、断格率、CV 分布、可疑行清单；
- 这是比 OCR 更硬的证据（OCR 会误判，几何不会）；先给“哪些行几何上就不对”，再花 OCR 预算。
- **2026-10-29 实测**（`work-c/geom_audit.json`）：50,686 行（≥3 格）/ 1,180,644 格；
  CV>0.35 **6.6%**、并格 **1.3%**、断格 **8.9%**，并集 **14.8%（7,506 行）**；
  `tall` 不可用（cells 的 `h` 是槽高，不是墨迹高）。几何只覆盖 14.8%，其余嫌疑来自丢格/内容错位，需 400 格与 OCR 补。

### P0-0.5 400 格人工审计（改成“修前/修后对照”，不当“要不要修”的闸）

**已知是红的**（C 33% 的 chosen 格比文楷多 ≥2 组件；一 10/10 错格），不再用 400 格确认“要不要修”。
400 格改为**修前/修后同一批格对照**，与 93 修复**并行**；修前版缩成与 2,000 行哨兵 pilot 合并的诊断样本，省一次人工。

- 修后版配额固定（总体绿不算绿）：
  - 横画类（一/二/三）20 格；
  - 申/形近字（甲/由/田/电/因/内）20 格；
  - 82 个合并格**全量**；
  - dedupe 吞框的 85 页抽 30 格；
  - 嫌疑行 50 格；
  - 8 张图标注字格各 1–2 格；
  - 绿线 = 总体 0 错 **且** 上述配额字类 0 错；总体绿但配额红 → 仍先修 93。
- **400 格全部人工标**，不看行标签；双 OCR 只预排序，不能当 ground truth；
- 每格五类：`内容错位 / 并格 / 断格 / 空 / 一字多格`；
- 分层报 `nc≠nl` / `nc==nl`、纯大字列/纯双列/混排；
- 报 95% CI；n=200 的 0 错上界约 1.5%，要判 <1% 需 n≥500；
- 产出 `work-c/cell_audit_400.json` + 修前/修后标注图。
- **2026-10-29 实测（400 格盲审，人读图）**：marked **108/400**；
  uniform **23/200 = 11.5%（Wilson 7.8–16.7%）**；类型 **并格 63 / 空 22 / 内容错位 7 / 断格 16**
  （并格+空 = **85/108 = 78.7%**）。分层：merged 26/30、blank 17/17、same_wrong 26/50、
  different 7/29、read_back 2/30、horizontal 5/20、confusable 1/20。
  → **红档**；修 93 先于 05；OCR 只排序（same_wrong precision 52%、different 24%、read_back FN 6.7%）。

**修前/修后双轨（写死，避免对比失效）：**

- **Track A（同批对照）**：旧 400 格按 `(key, line_text, k)` 或 bbox 重叠映射到新切；
  只报**可映射子集**的“旧错修好几格/仍错几格”，不当作新总体率；
- **Track B（新总体）**：新切后**重新抽 uniform 300**；绿线 = 新 uniform **0 错**（rule-of-three <1%）、
  merged 层 **<10%**、blank 层 **≈0**；
- 旧 400 的定向层只作错误类型对照，不混入新总体。

### P0-1 修 93 格框对位 + 重切（红/黄后执行）

- 格框 y 向按**行内墨迹 bbox** 收紧：墨迹不得触上/下格边，不得包含上一字底部；
- `cp` 用实际字高/行内墨迹，不用行距；`一` 的格高应接近一横，而不是 176；
- 重切后先跑**绝对几何**（见 P0-2 的 ①），确认 `一` 候选池不再全是“上字+横”；
- 产出新 `cells.jsonl`、`row_audit.json`；行对账 + 两字互换检查；
- **重切前不做相对中位闸**。

#### 93 修法（10 页实验后的结论）

**中心门控不够**：10 页 A/B（`/tmp/base10` vs `/tmp/gate10`）：
cells 3,967→3,766（−5.1%）、blank 10→5、merged 20→17、`h>1.25cp` 61→21；
但 `一` 仍带上一字碎片（`p01_0043_c02_l03_s024`，见 `/tmp/yi_gate.png`），
说明**格高/行框重叠**是主因，不是组件归属。

修法改为三层：

1. **栏级墨迹分带**：每栏按 y 投影的空白谷分“行带”，OCR 行框只用来给行带配文本；
   行带 y 边界不重叠，`一` 不再带上一条行带的底笔；
2. **行内谷切字**：在行带内按 y 投影谷切 N 格（`cut_line` 已有，但输入必须是行带，不是扩展后的 OCR 框）；
   切缝必须落在谷底，不许穿笔画；
3. **按字中心归属组件**：只保留“质心在该格核心区”的连通域；最后按 bbox 裁框；
   并格用“谷分裂 + 相邻空格合并”处理；空格外置（墨量 < 阈值）单列。

**10 页 gap-mid 实验（`work-c/exp/center_gate_10p/gap_mid`）**：
cells 3,967→3,943（base→gap）；merged **20→6**；`h>1.25cp` 61→18；blank 10→5；
鮓/渤 不变。**但 `一` 仍错**：gap-mid 后选到的 `p01_0043_c07_l16_s005` 是 **曰**（84×71），
标签却是 `一`——这是**行文本序列错位**，不是几何切格能修的；几何只解决并格，内容错位要标签校验。

**所以 93 修完还要过一道标签校验**：至少对 final chosen 1 格/字做视觉/OCR 复核；
不能指望几何把内容错位一起修掉。

先在 10–20 页验：并格率、断格率、空率、`鮓/渤/串` 回归、标签漂移 <0.1%；
通过再全量。**保留 v3c 的按行中缝校验**，不回退。

#### 混排（2 列小字 → 几个大字 → 又 2 列）专项

现状：`splits[ci]` 是**每栏一个**，用整栏 y-band 的墨迹算白廊；`full` 是**每行按宽度**判。
没有“大字带/小字带”的显式分段。因此混排是“半处理”：

- 大字行：`full=True`，取整栏；ok；
- 小字行：用整栏那一个 split；若该行 y-band 内缝被墨穿过（`leak>2%`）就退回 OCR 行框；
- 问题：
  1. 整栏 split 被大字污染，小字带的中缝 x 可能偏移；
  2. OCR 行框横跨两半时，`full` 可能误判为大字，整行切 N 格，格内是“左半+右半”；
  3. 小字带之间的中缝若左右移动，单 x 不适用。

修法（与 P0-1 一起做）：

- **按带分段**：每栏先分 y-band（小字双列带 / 大字带），每个小字带单独算 split；
- 或退一步：**按行算 split**（只用该行 y-band 的白廊），大字行不参与；
- `full` 加“单字高度/行高”与“两侧墨量”双条件，避免横跨两半的小字行被当大字；
- 混排页单独进 400 格审计分层，报告 `nc≠nl`、`merged`、错位率。

### P0-1.3 行级哨兵（先于 top-10，控制而不是选择）

**top-10 是“选择”，不是“控制”；池子/对位没控住时它没意义。**

- 每行取**首 + 中 + 末**三格 OCR（55,555 行 ×3 ≈ 16.7 万格，约 5 小时）；
- 首末抓“错位传到端”，中段抓“中段断/并后重新对齐”；先跑 2,000 行 pilot 定哨兵位置；
- **比较前剥标点**（句读圈/逗号不在格子里）；只对 `ab` 一致的行跑，或分 `ab / a_only` 报 FP；
- 哨兵命中 → **只定点重切该行/该段，禁止整行丢弃**；整行丢弃会掉真迹；
- 某格只在“该字还有别的 verified 样本”时才丢；否则保留并标 `suspect`；
- 若哨兵错配率（ab 组）>3%，先修 93 格框/混排，不进入 top-10。
- **2026-10-29 500 行 pilot 实测**（`work-c/sentinel_pilot.json`，rec-only，比较“格内容 vs 格自己的 label”）：
  clean 行错配 **16.8%**、几何可疑行 **32.0%**、ab **19.3%**、a_only **46.3%**；
  首/中/末 23.0% / 28.6% / 21.6%；两引擎都不一致 366/1,500（24.4%）。
  **结论：单格 OCR 误配率远高于 10%，不能做硬否决/硬闸；只能做人工复核排序。**
  第一次跑出 40%+ 是 pilot 自己的 bug（拿行位置 k 比，不是格 label）；修正后仍高，说明是 OCR 本身+标签噪声。
  因此行哨兵不能替代 400 格人工；P0-1.3 降级为“出复核清单”，不自动杀。

### P0-1.4 大字专项 OCR（高价值，但不替代正文）

- `big=True` 的格 **95,212 个（8.0%）**，全量 OCR 约 3 小时；
- 大字是字头/标题，观感权重最高；先保大字正确是合理的；
- 但 92% 是小字正文，`申/年` 这类小字不覆盖；**大字专项不能替代行哨兵/候选 OCR**。

### P0-1.5 选字前 OCR：每字 top-10 候选（重切后，先于 05_select）

**这是选字的前置硬闸，不是最后 QA。** 上一版把它写成“chosen 前 5 候选、选完再验”，位置偏后，是漏洞。

**top-10 不是用 05 的 score 直接 `argsort[:10]`。** 05 的 score 含 `q`（奖励碎边）、相对 medoid 距离和池内 size 中位；池子错时，top-10 只会是 10 个同样的错格（`一` 就是 1,962 个全错）。
生成顺序：

1. **93 修格框后**，先按 label 分组；
2. **绝对几何预筛**（不依赖池中位）：墨迹不触上/下格边、组件数、宽高比、平滑度；
3. **排序**：到同字中位几何的距离 + 与池中心距离，**不使用 `q`**；
4. **多样性**：48×48 向量做 NMS/聚类，避免 10 个近重复；取 10 个不同簇的代表；
5. **OCR 否决**（v6+v5 都不一致才 reject）；verified 才进 05；
6. 05 在 verified 池上重算 medoid，**score 里删掉 `q`**。

对 5,299 个 label，各取**前 10 个候选格**（上述流程），共 **≈5.3 万格**；
- 每格跑 v6+v5 单格 OCR：
  - 任一引擎读回本 label → `verified`，进 05_select 候选池；
  - 两个引擎都读成别的字 → `reject`（或进人工桶，按 FP 标定决定）；
  - 10 个全 reject → 扩到第 11–20 个；仍无 → 该字无 verified 真迹，走 GAN/ribbon；
- **05_select 只读 verified 池**；chosen 5,299 全部带 OCR 记录；
- **训练 pairs 只用 verified chosen**；任何未过 OCR 的格子不得进入 `pairs.npz`；
- 成本：5.3 万格，按 5,287 格≈10 分钟，约 **1.7–2 小时**（batch 后更低）；
- **所有 OCR 结果统一写 `work-c/cell_ocr.jsonl`**，按 `file` 为键：
  `{key, li, sub, file, engine, text, conf, line_label, verdict, source_pass}`；
  哨兵/大字/top-10/400 格/成品反查都读这一张，禁止各自为政。
- 第二优先：嫌疑行 40.6 万格（约 14 小时，需 batch）；`nc==nl` 两字互换若 400 格中 >0.5%，扩到常用 3,000 字的行；
- OCR 只做否决/降权（双引擎都不一致才否决），形近字不一致进人工桶；FP 先按 1,562 可靠字标定；
- `n<2` 226 字：强制 OCR + 人工核，不直接丢；
- 人工三桶（720 个多数错位标签、形近字、常用 500）单列 2–3 千格，约 1–2 天。

**原则：OCR 在“进池/进训练”之前跑；最终成品的反查 OCR 只做回归，不是第一道闸。**

### P0-2 选优闸（绝对 → 重切 → 相对）

候选池 = P0-1.5 的 `verified` 池；顺序（AND）：

1. **绝对几何**（不依赖中位）：墨迹不触格边、组件数、宽高比、平滑度（周长²/面积）；
   - `一`：宽高比 ≥2.5、1 组件、不触上下边；
   - `申`：宽高比 0.4–2.5、组件数 = 文楷 ±1；
   - `四`：外框完整、平滑度闸（抓碎边）；
2. **重切后**才允许相对闸：
   - `min(w,h) ≥ 0.55 × 同字同类（big/small）中位`（申 0.53、年 0.42 被拦；全池约淘汰 0.79%，误伤低）；
   - 常用 500 字内 `min 边长 < 2/3 × 同类中位` 的格不进（软优先大字）；
3. **`q` 直接删除**，不封顶——它奖励锐边即奖励碎边；
4. 87 Dice <0.15 只作下限，不作主闸；
5. 错位行默认不进 chosen，除非单字 OCR 确认；
6. shortlist 每字 2–3 个候选，最终仍只选 1 个目标（不是多目标）。
