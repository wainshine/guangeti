## 1. 共用库（一次修，两线受益）

### S1 `fontbuild.py` 的 `fontRevision` 只取前两段

**问题**：`VERSION="1.6.1"` 写进 name 表正确，但 `head.fontRevision` 恒为 `1.0`（B 线两次点名）。

**改法**：TrueType 的 `fontRevision` 是 16.16 定点数。按惯例取 `major.minor`，
三位版本号映射为 `major + minor/10 + patch/100`（`1.6.1 → 1.061`），并在 `fontbuild` 里集中换算。

**验收**：`TTFont(...)['head'].fontRevision` 分别读出 `1.061`（A）与 `1.010`（B v1.1.0）。

**影响**：所有字体的 `head` 表变化 → 二进制哈希全变 → **A、B 都要重建一次**。
因此这一项应和各自的下一次重建合并，不要单独发版。

## 3. 执行顺序

```
1. S1（fontRevision）+ A1 + A2 + A3 + A4 + A5   ← 代码，约 2–3 小时，可并行
2. 重建：07(干净轮廓) → 11 → 13 → A2(孔洞) → 23(面板) → 14(带闸) → zip
3. A6（人工图）→ 重新打包 → 同步 DATA / PROJECT_STATE / RELEASE-v1.6.2
4. 全库自审计（链接 / 校验和 / E 编号 / A-B 互引）
```

**注意**：S1 会让二进制全变，所以**先改代码、后一次重建**，不要中间打包。
