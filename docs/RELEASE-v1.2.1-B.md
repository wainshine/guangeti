# GuanGe Kai B v1.2.1

> 随主版本 **GuanGeKai v1.6.5** 发布。同一项目、两个字形来源：
> A = 四书刻本《四書白文》（家族名 `GuanGe Kai`，v1.6.5）；
> B = 史记抄本（家族名 `GuanGe Kai B`，本包 v1.2.1）。

**Version 1.2.1** — 相对 v1.2.0 的变更：**常用字孔洞修复**（`国/园` 恢复孔、`年` 不再丢孔）

> v1.2.0 的混合检查点变更见下；v1.2.1 只改孔洞处理与闸门，模型与工作点未变。

**Version 1.2.0（同批）** — 相对 v1.1.0 的变更：**混合检查点**，只用第二个模型去救第一模型过不了守卫的字。

## 规则（确定性，先主后副）

```
对每个合成字 ch：
  ① ep80（主模型）生成 → 过守卫 → 采用（gan）
  ② 否则 ep90（加权模型）生成 → 过守卫 → 采用（gan_ht）
  ③ 都不过 → ribbon 回退（ribbon_fb）
```

同一个字永远走同一条路径，任何人重跑结果一致。守卫三条不变（空输出 / 墨量 [0.6,1.5] / 连通域差 ≤3）。

**为什么 B 的顺序与 A 相反**：A 的加权模型**全局更好**（chamfer 5.92→5.85），所以 A 用加权模型打头、
ep80 补位；B 的加权模型**全局更差**（5.60→5.67、墨量 +4.3%），只有困难字上更好（B/E12：对 ep80
成对胜率 70%）。所以 B 必须让 ep80 打头——这样**每个字的输出只会变好或不变**，不存在全局倒退。

## 效果

| 项 | v1.1.0 | v1.2.0 → v1.2.1 |
|---|---|---|
| GAN（ep80） | 15,784 | 15,784 |
| GAN（ep90 救回） | 0 | **544** |
| ribbon 回退 | 1,135（6.7%） | **591（3.5%）** |
| 干净集 Dice / 墨量 / chamfer | 0.523 / 1.009 / 5.60 | **0.523 / 1.009 / 5.60（完全不变）** |
| 孔洞：完全丢孔 | 1.9% | **1.0%**（全字集 157/15,265；白名单 0 失孔） |
| 字重比（合成/真迹） | 1.071 | **1.082** |

干净集三项**逐位相同**，这是"先主后副"的结构性保证：所有原本合格的字仍用 ep80 的输出。

> 孔洞一行两栏口径不同：v1.2.1 的 **1.0%** 是 `71_holes.py --n 0` 的全字集实测（157/15,265），
> v1.1.0 的 1.9% 沿用当时的记录。量级可比，但严格差值需按同一口径重测。

## provenance 四态

```
real / gan（ep80）/ gan_ht（ep90 救回）/ ribbon_fb
```

复现必须知道每个字来自哪个模型：`data/release-b.json` 记录主模型与副模型路径。

## 已知限制

- **孔洞**：完全丢孔 **1.0%**（全字集 157/15,265，不是 300 字抽样），仍有 12.2% 的字比文楷少孔；
  根因是抄本断笔与细接缝（B/E9、A 线 E38 结论一致），不是分辨率，接受现状并披露。
- **困难字的 GAN 输出仍不如主体**：544 个救回字是模型最吃力的一档（E12 显示其局部粘连率
  4.68%，主体是 3.9%），但**仍优于原来用的 ribbon**（6.40%）。
- chamfer 5.60 相对真迹地板 3.57 差 57%，是 150 dpi 扫描的结构性天花板（DATA-B §5.8）。
- 未做 hinting。
