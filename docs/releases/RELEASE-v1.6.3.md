# GuanGe Kai v1.6.3（A 四书）

> 本版把**回退率从 9.5% 降到 7.9%**：多 306 个字用 GAN 而不是弱渲染。
> 做法是给训练按字形复杂度加权，让模型在笔画多的字上更用心。

## 本版变更

| 项 | 内容 |
|---|---|
| **复杂度加权训练**（E39） | `21_train_gan.py` 新增 `--weight-complexity`（两线共用）。按目标墨量给样本加权 `w=clip((ink/median)^0.5, 0.5, 3.0)`，从 ep80 续训 20 轮 |
| **采用 ep090** | 干净集 chamfer 5.92 → **5.85**，墨量 0.991 → 0.981（在 ±0.02 内）；ep100 反而变差（5.97），不采用 |
| **回退率** | 9.5%（1,833 字）→ **7.9%（1,527 字）** |
| **字形规模** | 与 v1.6.2 相同（20,992 = 1,675 真迹 + 19,317 合成），只是合成字的来源构成变了 |

## 换血结构（如实披露）

| 变化 | 数量 |
|---|---|
| 从 ribbon 改为 GAN 采用 | **1,034 字** |
| 从 GAN 掉回 ribbon | **728 字** |
| 净减少回退 | 306 字 |

也就是说这不是单向改善：加权训练让 1,034 个复杂字画得足够好、过得了守卫，
同时有 728 个原本通过的字被新模型画糊、重新被拦下。

## 已知瑕疵

**目视可见局部粘连**：`乿`（右上）、`傒`（右下）、`僎`（右半）、`儞/儠`（内部）
在新模型下笔画粘连，但仍通过了守卫——**说明守卫的「连通域差 ≤3」对 17 笔以上的字太松**。
对比图见 `docs/images/cmp-v162-v163.png`（三行：文楷 / v1.6.2 / v1.6.3）。

这是下一版要解决的主要问题：不是模型画不好，而是**没有可靠的方法判断"这个复杂字画对了吗"**。

## 已知限制（延续）

1. **孔洞缺陷**：`四/国/目/自/年` 等字仍实心。E38 已证明高 dpi 只能恢复 22% 的缺孔字，
   多数是原书断笔所致，**无工程解法**。实测：孔数一致 22.9%、完全丢孔 2.8%。
2. 合成字比真迹重约 17%（5–7% 为字集构成，约 5% 来自模型输出字面偏小）。
3. 未做 hinting。
