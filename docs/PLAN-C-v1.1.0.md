## 2. 归因（修订）

### G1 选优无绝对质量闸（成立，P0）

`05_select.py` 的 `score = d − 0.25q − 0.15m + 0.35·sz + 0.15·red` 全是相对量；
C 线跑 `--min-samples 2 --prefer-clean bad`，**没有 `--drop-if-all-flagged`**；整簇皆坏时照样选出。
审2 补充的机制（鲁棒均值收敛到最紧簇、碎片彼此最像）成立，W1 要把注释和阈值一起写清。

### G2b “地板”解释（修正）

- 事实：C 的发布字体 chamfer **6.87**，已低于同字地板 **6.98**；A 是 5.92 vs 地板 5.16（高 15%）。
- 审2 指出：回归模型向均值收缩，**低于地板不等于达标，可能是变糊**；并且同一页同字的
  chamfer 仍有 **6.80**（跨页 8.81，审2 实测），说明地板里很大一部分不是“抄手差异”，
  而是归一化/切字/二值化噪声。
- 结论修正：**不追平 A/B 仍然成立，但理由不是“C 天生地板高”，而是“地板本身含管线噪声，
  且模型在向均值收缩”**。因此 v1.1.0 要加一个“地板分解”实验（E25），先分清
  “同页/同尺寸/同手”的噪声与真正的跨页差异，再谈模型上限。

### G3 评测 ≠ 生产（部分成立，降优先级）

审2 实测：发布字体 0.443 / 16.6% / 7.11（本线复算 6.87，差异来自 chamfer 的质心对齐实现），
模型级 0.444 / 15.4% / 6.64。**Dice 基本不变，chamfer 差 0.23–0.47（约 3–7%），崩坏率差 1.2pp。**
所以：
- “评测完全不代表发货”不成立（Dice 一致）；
- 但“评测低估了结构误差”成立（chamfer/崩坏率更差），W4 保留，优先级从 P1 降为 P2。

### G4 生成侧三个口径问题（成立；其中一条抗辩）

- **close 1 恒等**：成立（`MORPH_ELLIPSE(1,1)` 为单像素核）。
- **守卫组件数 >2**：成立；审1 实测 400 个 s2t 码位 |Δ|≤2 占 73.0%，且 ribbon 在 C 的细墨下
  崩坏率约 61%（E9）——守卫把“可能繁体化”换成了“大概率断笔”，这是 v1.0.1 的隐性代价。
- **距离变换“死区”**（审1 认为 v1 诊断错误）：**本线抗辩成立**。`distanceTransform` 的 dtype 是
  float，但对二值掩膜，最近零像素的距离最小值为 **1.0**，所以 `dto<=delta` / `dt>1-delta`
  在 `delta<1` 时选不到任何像素。实测：delta=0.3/0.6/0.9 的膨胀/腐蚀面积变化均为 **0**，
  delta=1.0 才 +116 px。**死区真实存在**。
  但审1 指出的其余三条（4% 容差、±5px×6 次钳制、孔洞回退即 break）也成立，且可能是 ep20
  字重压不下来的主因。W2.2 改为：**先插桩**记录停步原因，再决定修法（2× 超采样只解决第一条）。
- 两套墨量曲线并存：`target_ink_256`（38.7258/0.5701）与 `ribbon_fit.json`（39.4438/0.4318）
  是不同阶段的拟合，W2 重标定时**两条都要动**。

### G5 标签口径（成立）

a_only 665（12.6%），中位样本 4；双见证一致率 93.0%（含 a_only 90.3%）。
审1 实测：3,466 个标签有 ab 实例可替换；**硬底 261 字**（全部实例都是 a_only，丢弃必失守）。
E20 应先跑替换率，目标 665→约 261（4.9%）。

### G7 干净集测错对象（新，审2）

3,213 里 98.3% 是 real；0.444 被真迹方差主导。**旧 54 字 0.414 是偏置子集**；
W1.5 的 **300 字留出实测 0.585 / 5.65 / 1.0%**（干净 medoid 目标，与 A/B 的 617 稀有字集不是同一任务）。
所以“C 的模型泛化比 A/B 低 0.13”**不成立**；C 的真实弱点是**页留出上的目标方差 + 字重**
（0.444 / 14.4% 那组），不是模型写不出字。

### G11 切格层错误（用户实测，v2.2 追加，优先级在 G1 之前）

用户指出：大字一列、小字两列；两列时字只占半边，切出的格子有半边空；小字未放大；几个小字被切进一格。
本线用 `scripts/99b_audit_cells_c.py` 复核 `chosen`（5,287）：

```
纵向合并（h>1.25·cp 且 y 投影有两个 >25% 高度、间隔 >8% 的墨团）：**1**（洒 = 洒+西，h=1.35·cp）
  初版按“两个墨团”判到 10，但 二/六/言/這/詈 等是**分离笔画**，不是合并；收紧到 h>1.25·cp 后只剩 1。
尺寸异常：11 large（>1.15·cp）+ 2 tiny（<0.30·cp）= 13
  过小例：惮 0.20·cp、吕 0.30·cp（吕是“口+口”，本身小，不是错切）
碎片（小连通域 + 远 + 贴边，初版判据）：125（多为正常点/撇；真碎片例：讞 下坠、娓 右句读）
偏离 slot 中心 >0.18·max(w,h)：**716**（0.20 为 591；v2.2 写的 604 是旧口径，已作废）
原始 1,214,431 格：tiny 42,439、large 90,560、bad 91,085
```

典型：`洒`（p35_0030_c02_l13_s001）一格两个字；`讞` 下带碎片；`娓` 右带句读圈；
`惮`（37×69，cp=183）源分辨率太低。**这些错误会进入 chosen、训练对和干净集目标**，
所以 W1.5 必须先于 W1.1/W0.1。

**v2.3 的两处修正**：

- **横向合并也要防**：`93` 的 `full = (bx1-bx0) > 0.62*(R-L)` 会把“半栏小字”判成整栏，
  一格装两个字。W1.5 加一条：同一栏有两条行框时，两条都不得判 `full`。
- **“小字未放大”归因错误**：最终字面尺寸是 big 874×846 / small 867×842（差 ~1%），
  norm 并没有忘记放大；糊的原因是 300 dpi 下小字只有约 270 px，`76/77` 要出 512 轮廓，
  等于 **1.9× 放大**。这条修不在切格层，应在 W2/W3 的后处理（去噪/追踪/超分）里，
  不能记在 W1.5 头上。
