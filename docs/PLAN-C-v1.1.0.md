## 2. 归因（修订）

### G1 选优无绝对质量闸（成立，P0）

`05_select.py` 的 `score = d − 0.25q − 0.15m + 0.35·sz + 0.15·red` 全是相对量；
C 线跑 `--min-samples 2 --prefer-clean bad`，**没有 `--drop-if-all-flagged`**；整簇皆坏时照样选出。
审2 补充的机制（鲁棒均值收敛到最紧簇、碎片彼此最像）成立，W1 要把注释和阈值一起写清。

### G2b “地板”解释（修正）

- 事实：C 的发布字体 chamfer **6.87**，已低于同字地板 **6.98**；A 是 5.92 vs 地板 5.16（高 15%）。
- 审2 指出：回归模型向均值收缩，**低于地板不等于达标，可能是变糊**；并且同一页同字的
  chamfer 仍有 **6.80**（跨页 8.81，审2 实测），说明地板里很大一部分不是“抄手差异”，
  而是归一化/切字/二值化噪声。
- 结论修正：**不追平 A/B 仍然成立，但理由不是“C 天生地板高”，而是“地板本身含管线噪声，
  且模型在向均值收缩”**。因此 v1.1.0 要加一个“地板分解”实验（E25），先分清
  “同页/同尺寸/同手”的噪声与真正的跨页差异，再谈模型上限。

### G3 评测 ≠ 生产（部分成立，降优先级）

审2 实测：发布字体 0.443 / 16.6% / 7.11（本线复算 6.87，差异来自 chamfer 的质心对齐实现），
模型级 0.444 / 15.4% / 6.64。**Dice 基本不变，chamfer 差 0.23–0.47（约 3–7%），崩坏率差 1.2pp。**
所以：
- “评测完全不代表发货”不成立（Dice 一致）；
- 但“评测低估了结构误差”成立（chamfer/崩坏率更差），W4 保留，优先级从 P1 降为 P2。

### G4 生成侧三个口径问题（成立；其中一条抗辩）

- **close 1 恒等**：成立（`MORPH_ELLIPSE(1,1)` 为单像素核）。
- **守卫组件数 >2**：成立；审1 实测 400 个 s2t 码位 |Δ|≤2 占 73.0%，且 ribbon 在 C 的细墨下
  崩坏率约 61%（E9）——守卫把“可能繁体化”换成了“大概率断笔”，这是 v1.0.1 的隐性代价。
- **距离变换“死区”**（审1 认为 v1 诊断错误）：**本线抗辩成立**。`distanceTransform` 的 dtype 是
  float，但对二值掩膜，最近零像素的距离最小值为 **1.0**，所以 `dto<=delta` / `dt>1-delta`
  在 `delta<1` 时选不到任何像素。实测：delta=0.3/0.6/0.9 的膨胀/腐蚀面积变化均为 **0**，
  delta=1.0 才 +116 px。**死区真实存在**。
  但审1 指出的其余三条（4% 容差、±5px×6 次钳制、孔洞回退即 break）也成立，且可能是 ep20
  字重压不下来的主因。W2.2 改为：**先插桩**记录停步原因，再决定修法（2× 超采样只解决第一条）。
- 两套墨量曲线并存：`target_ink_256`（38.7258/0.5701）与 `ribbon_fit.json`（39.4438/0.4318）
  是不同阶段的拟合，W2 重标定时**两条都要动**。

### G5 标签口径（成立）

a_only 665（12.6%），中位样本 4；双见证一致率 93.0%（含 a_only 90.3%）。
审1 实测：3,466 个标签有 ab 实例可替换；**硬底 261 字**（全部实例都是 a_only，丢弃必失守）。
E20 应先跑替换率，目标 665→约 261（4.9%）。

### G7 干净集测错对象（新，审2）

3,213 里 98.3% 是 real；0.444 被真迹方差主导。**C 的模型泛化是 0.414（n=54）**，
而 A/B 分别是 0.549/0.523（617 个生字）。**“C 用 5,287 对训练、生字泛化反而低 0.13”**
是本轮最该盯的数字。W0 把 KPI 改成三个数（见 §3）。

### G8 pairs_clean 被污染（新，审2/审3）

`pairs_clean.npz` 建于 `96_fix_labels` 之前（含 23 个已重标 + 32 个应弃格）。
0.443/6.87/16.6% 是在旧参照集上测的。W3 必须先重建 clean，再重测 ep20/30/40。

### G9 大/小字混排（新，审1）

审1 实测：58.3% 的标签同时有大字/小字实例；chosen 里 95.4% 来自双行小字，大字字头只有 241 个；
大小字 fill 中位差约 9%。这既影响训练目标，也影响“字头”作为风格基准。W1 加分层统计，
E24 验证是否要单独建模。

## 3. KPI 重定义（W0，先做）

发布文档与内部评估一律报告**三组数**，不再用一个 Dice 概括：

1. **页面留出集（全部 3,213）**：风格一致性；按 provenance 拆 real/gan/ribbon。
2. **未见过字（54）**：泛化；注明 n，不与其他线混比。
3. **缺陷率**：崩坏率拆成「模型缺陷 / 目标方差 / 标签错」三部分（E22）。

Dice 只作回归线；字重/一致性单独报（ink/WK、字号扫描、capKS）。

  - **机制注释**：鲁棒均值会收敛到最紧簇，碎片簇最紧——写进代码注释，防止下次调参放回。
- W1.2 `94_label` 格级对账：不一致 → **人工复核桶**（审3：单字 OCR 对异体字误判率高，不能自动丢）。

  加回归测试：重跑 94→96→05 与当前 chosen 标签集合一致。

### W2 墨量/观感（1 天；需 Q1 决策）

- W2.1 **先做灰阶笔宽实验（E23）**：用灰度剖面 FWHM 测“同字笔宽/文楷笔宽”，与二值墨量比对照。
  审1 指出 E5 的阈值从 0.42 换到 0.58 会让墨量比 0.539→0.629（±8%），0.594 缺一个阈值无关的锚。
- W2.2 gain 重标定（修正算术）：当前 0.594 @ gain 1.10，近似线性（每 +0.1 gain ≈ +0.054 ink/WK）：
  - 对齐 B（0.73）→ gain ≈ **1.35**；
  - 对齐 A（0.835）→ gain ≈ **1.55**；
  - 审1/审3 的 1.25/1.35 对应的实际目标分别是 0.675/0.729，v1 表里的 0.72–0.74、0.80–0.84 是错的。
- W2.3 去除化死区：先插桩（4% 停 / clamp / 孔洞回退），主因若是孔洞回退，2× 超采样无效；
  改为“回退该步但继续”或“对重字形单独放宽保护”，再验收“实际/目标 ∈ ±8% 的比例 ≥90%”。
- W2.4 两条曲线统一：`target_ink_256` 与 `ribbon_fit` 由同一脚本重拟合、同一 JSON 落盘。
- **验收**：ink/WK 达到 Q1 选定目标 ±0.03；字重偏差 0.95–1.05；孔洞不劣化。
