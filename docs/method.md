# 技术路线 / Method

## 1. 从扫描到单字

* **渲染与纠偏**：PDF 每页是一张 ~6700×6000 的 JPEG（约 300 dpi）。用投影/Hough 估页面倾角，旋转 0.1–0.4°。
* **去除句读圈点**：原书圈点是**红色**的，但本项目使用的 PDF 已去色（实测无红色像素），
  故不能用颜色分离：以「厚度 + 连通域」判据剔除，细于 2.3 px 的孤立碎片（圈点弧线、纸褶）
  在分配前整段处理。
* **去除版框**：长核形态学开运算取横/竖框线，膨胀后从墨迹中减去；再过滤细长连通域。
* **文字块与栏**：以 121×121 均值滤波得到墨迹密度，取密度 > 22% 峰值区域为文字块；
  以「每列有墨的行数占比 > 5%」作为栏的判据（栏间走廊近乎全白）。
* **字距与字元分割**：对整页各栏的归一化纵向投影做自相关，得到字距（约 310 px）；
  每栏在此基础上拟合相位与缩放，使切分线落在空白带上。
* **字元归属（两遍）**：先按连通域质心归格；再把「与该格外框重叠 >45%」的未分配连通域
  （被切开的撇、捺、点）吸回本格，迭代两次。最后以本格所有连通域的联集作为字形掩膜，
  **不再对裁剪图重新二值化**——邻字碎片因此无法混入。

## 2. 标注

* **逐页 OCR**：RapidOCR（PP-OCRv6）在 150 dpi 上侦测直栏、整栏辨识；干净页面的逐栏辨识约 99%，
  但与《四书》标准白文的**字面一致率为 87.1%**（5 万余行中有一致结果者），差异多为异体字
  （爲/为、巳/已、雲/云），并非辨识错误。两个数字口径不同，勿混用。
* **标准文本对齐**：以《四书》标准白文（大学/中庸/论语/孟子，OpenCC 转繁）为词典，
  对每页做 `difflib` 局部对齐，得到「第 n 个切片 ↔ 第 m 个标准字」的映射。
* **以 OCR 为主、文本为辅**：OCR 与标准文本一致率约 90%；不一致时仍以 OCR 为标签
  （写本保留异体字，如 爲/为、巳/已、雲/云），文本只用于页序与位置校验。

## 3. 每字最优样本

同一字常有数十至上千个样本。作法是：

1. 每个切片正规化为 48×48（按墨迹外框、等比）。
2. 以「均值 → 丢弃最差 25% → 重算均值」迭代 3 次，得到稳健中心。
3. 综合评分 = 到中心的距离 − 0.25·锐度 − 0.15·方正度 + 0.35·字面尺寸离群 + 0.15·红色残留。
4. 取评分最低者。**仅出现 1 次、无法做同字聚类校验的字一律不用**（实测这类字确有错标），
   因此 2,292 个字标签中只保留 1,675 个进入字体。

## 4. 向量化与字身框

* 二值化（Otsu，限制在 120–200）→ 去斑 → potrace（`turdsize=8, alphamax=1, opticurve`）。
* 每个字按其**格心**映射到 em：字距 310 px ↔ 880 units（UPM 1000，基线 0，字面 0–880）。
* 为使真实字形与生成字形混排一致，再把每个字的外框按 80% 权重向基线字体（霞鹜文楷）
  的同字外框对齐（等比缩放 + 平移），保留 20% 写本的原始大小差异。
* TrueType 方向：外轮廓顺时针、内洞逆时针；三次曲线用 cu2qu 转二次（误差 ≤ 1 unit）。

## 5. 缺失字的生成

发布版（**v1.5.0**）采用 **GAN**：结构仍由文楷骨架给出，笔形由模型生成；GAN 输出触发守卫时
回退到**带状扫掠**（v1.3.x 的发布方案）。

### 5.0 发布版：GAN（v1.5.0）

- 模型：zi2zi U-Net + **5 层 PatchGAN（≈70×70）** + hinge loss + 数据增强，80 轮。
- 输入文楷渲染，输出写本风格字形；训练数据是 1,634 对（每字一张中位样本）。
- **守卫**（廉价，不比对拓扑）：空输出 / 墨量比不在 [0.6,1.5] / 连通域数与文楷相差 >3
  → 整字回退带状扫掠。全量触发 9.5%。
- 干净集（617 个从未训练的字）：Dice 0.549、骨架 chamfer 5.92px（真迹互比地板 5.16px）。

### 5.1 回退方案：带状扫掠（v1.3.x 发布版）

对每个缺失字：

1. 用霞鹜文楷（OFL）渲染 256×256 点阵，提取骨架与每点半宽；
2. 每条笔画从真字的「逐笔相对宽度」分布抽样一个墨量系数（`dip`，先幂次再归一，保证均值 1.0）；
3. 沿骨架扫掠**带状多边形**：左右偏移线的终点错开 → **斜切端头**（不再是圆头）；
4. 叠加沿程 `taper`（起笔略重、收笔略轻）；
5. 与基线字形做 IoU 守门（<0.7 回退），potrace 向量化，按 100% 权重对齐基线字身框。

> 为什么不是形态学滤波：滤波只能整体加粗/减细，做不出端头形状；
> 而**圆头是「圆盘点印」的产物**，换成带状扫掠后端头自然成切角。
> 实测（91 字无泄漏集，掩膜级）：墨量 1.063、端帽 KS 0.068、逐笔 std 0.223（真迹 1.000 / — / 0.248）。
> 字体级（矢量化后）：Dice 0.432、墨量 1.146、端帽 KS 0.124。
> 逐笔宽度分布由 2,292 个真字的 45,042 条笔画拟合（见 EXPERIMENTS E19）。

效果：「竖粗横细、血肉加重」，视觉重量接近写本；但**没有墨笔笔锋**，本质上是加粗的楷体。
这一点在 [PROJECT_STATE.md](PROJECT_STATE.md) §2 已明确标注。

## 6. 已知偏差

* 写本用字只有 2,292 个标签（保留 1,675），且多为高频字；生成字在笔锋、起收上与真实字有可感知差距。
* **GAN 与带状扫掠都不理解笔顺**：GAN 从像素分布学形状，带状扫掠按骨架扫掠，
  两者都没有笔顺/结构的显式表示——这是仍未解决的根本问题（E24/E27 的闸门失败即源于此）。
* **小字号偏重**：v1.5.0 的合成字在 12–14px 比真迹重 12–20%。
* 带状扫掠（回退方案）的横折仍是圆角；GAN 在 10 个含横折的干净字上，
  转角窗口与真迹的 IoU 0.363（文楷 0.275、ribbon 0.266），**更好但仍未解决**。
* 未做 hinting；小字号渲染依赖系统 autohinter。
