## 2. 新发现

### 2.1 [A] P1 — 发布制品不可复现：补位模型阈值 −0.45 从未进入代码

- 发布说明与实验记录都声称补位字用**阈值 −0.45** 生成（`docs/RELEASE-v1.6.4.md:13,33`、
  `docs/EXPERIMENTS.md:1342`），但提交代码里硬尾分支是**硬编码 −0.05**：
  `scripts/10_generate.py:122`（`hard(...) > -0.05`）；`--threshold` 参数（:424）是**死参数**，
  全文件无处引用；`git log -S '0.45' -- scripts/10_generate.py` 为空（该文件任何提交都没出现过 0.45）。
- 复现取证（6 个 `gen80` 字，按发布管线重放）：
  - 主模型 ep90 @ −0.05：与发布字形偏差 ±1.3% → 管线复现方法本身无误；
  - 补位模型 ep80 @ **−0.45：偏差 −1.7% ~ +0.5%**，与发布字形吻合；
  - 补位模型 ep80 @ **−0.05：偏差 −3.3% ~ −15.5%**，系统性偏轻。
- 结论：**发布制品是用 −0.45 生成的，但仓库代码只会生成 −0.05 的补位字**。任何人按当前代码
  重跑 `10_generate.py --method gan`（配合 `GAN_CKPT`/`GAN_HARDTAIL` 环境变量），得到的 728 个
  补位字墨量比约 0.932（vs 主模型 1.041，差 10.5%，正是 E40 表格里被否掉的那一行），
  混排接缝问题回归；与「任何人重跑结果一致」的确定性承诺相悖。
- 改进：把硬尾阈值参数化（学 B 线 `data/release-b.json` 的「单一口径 + 启动告警」设计，
  `60_generate_b.py:244-249`），把 −0.45 提交进去；E40 补上精确复现命令（环境变量 + 阈值），
  否则复现者只能靠猜。

### 2.2 [B] P1 — 常用字孔洞闸空转：「国」0 孔过闸

- `63_qa_b.py:146` 的常用字检查是 `zero = [c for c in args.common_holes if c in
  holes.get("lost_chars","")]`，而 `lost_chars` 来自 `71_holes.py` 对 **n=300、seed=0 固定随机样本**
  的统计（`71_holes.py:68-70`）。清单里的字只要**没被抽进样本**，就永远不会被检查。
- 实测发布字体 `GuanGeKai-B-Regular.ttf`：**「国」0/1 孔（完全实心）**，而「国」就在
  `--common-holes` 清单里；`work-b/log_qa.txt` 却打印 `common-hole chars without a counter: 0`，
  QA OK。闸门形同虚设地放行了清单内的已知缺陷。
- 对照：v1.0.0 的 P0 大字孔洞（四/國/目/自）本轮**实质修复**（实测 四 2/1、國 6/2、目 2/3、自 2/3），
  说明 `--close 7` + `repair_counters` + 混合检查点有效；「国」是漏网个案，但恰恰证明闸设计有洞。
- 改进：对 curated 清单单独全量渲染检查（不走随机样本），或直接用 `71_holes.py --n 0`
  （全 cmap）的 `lost_chars` 做判定；A 线将来移植该闸时同样适用。
