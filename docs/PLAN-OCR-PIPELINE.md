# OCR 分层方案 v1.1（对抗性审查后修订）

> 2026-10-31。修订点：VLM 覆盖**全部 verified 池行**，不是只跑争议行；
> DP 对齐改为**未验证组件**，单设门；新增回归与 canary；A/B 路径只作模板；
> 全量 55.5k 行明确禁止。成本仍 ≤100 元。

---

## 0. 总原则

1. **百万格永远不逐格 OCR**；OCR 以页/行为单位，格只做对齐。
2. **有对照文本**（A/B）：PP-OCRv6 + v5 + 文本对齐，不调 LLM。
3. **无对照文本**（C）：PP-OCR 给框和初读，**VLM 跑全部 verified 池行**，不只跑争议行。
4. **不能联网/预算为零**：本地 PaddleOCR-VL 替代线上模型。
5. **人只处理尾巴**：分歧格 + 全部回归格 + 不可对齐格。
6. **不重切全量**；不重跑 90 轮；v1.2.1 冻结。

---

## 1. 决策树

```
A/B（有对照文本）
  → PP-OCR v6+v5 整页 OCR
  → 行文本 ↔ 对照文本 DP
  → 字符框/槽位回填
  → CER 门 + 差异人工
  → v1.3 不执行，仅作新数据模板

C（无对照文本）
  → PP-OCR v6+v5，只对 verified 覆盖的 4–5k 行补字符框
  → 行级 VLM 跑这 4–5k 行（全部，不是只跑争议）
  → 用字符框锚定 DP 对齐
  → 多见证 + 回归/canary 门
  → verified 池
  → 人工尾巴 300–400 格 + 全部回归
```

---

## 2. A/B：有对照文本（v1.3 不执行）

- 只作为**新数据接入模板**；
- v1.3 不动 A/B 已发布标签；
- 若未来执行：
  - 行文本与对照文本 DP，CER ≤0.5%；
  - 与现行标签 diff；
  - 差异格全部进人工，禁止静默覆盖；
  - 不调 LLM。

---

## 3. C：无对照文本

### 3.1 PP-OCR：只补 verified 覆盖行

- 全量 `ocr_v6.jsonl` / `ocr_v5.jsonl` 已在盘上；
- 缺的是**字符框**；
- 只对 verified 池覆盖的 **4–5k 行**定向重跑双引擎，拿字符框；
- 预计 **约 15 分钟**；
- 不把全量 2.1 h 放进关键路径；
- 若坚持全量重跑：必须产出行文本 **drift diff**，drift 行全部进争议/人工。

### 3.2 行级 VLM：全部 verified 行

触发范围不是“只跑争议”，而是：

```
chosen 5,302 格所在行
+ 572 锚点所在行
+ 266 zero-AGREE 字所在行
≈ 4–5k 行
```

理由：

- calib28 的 4 个匹配器误报，五个“争议”条件一条都不命中；
- 高置信行直接入 verified 会静默带回错标；
- 今天没有任何读者的置信度值得直接信任（DeepSeek 假接受时自报 0.98）。

**删除“高置信行直接入 verified”快捷通道。**

### 3.3 行级 VLM 输入与协议

- 300 dpi 灰度行裁剪；
- 长边 ≤2400，只缩不放；
- 不印标签；
- 整行竖排转写，返回纯汉字；
- DeepSeek Flash：`thinking:disabled`、`temperature=0`、`detail=high`、`max_tokens=500`；
- 本地回退：PaddleOCR-VL 1.6，Ollama，1.8 GB，5–8 s/行。

### 3.4 对齐：DP 是未验证组件，单设门

**现状**：

- 仓库没有行↔格 DP 对齐脚本；
- 94_label 的 SequenceMatcher 是行-行，不是行-格；
- 字符框匹配器是几何的，不是序列的；
- DeepSeek 行转写复跑：93 可读格中只有 57 行长度=格数，全分母严格位置 54/93 = 58.1%。

**定义**：

```
DP 只做“VLM 字符序列 ↔ PP-OCR 字符框序列”的对齐；
再由字符框→格框的几何映射得到格标签。
不允许无锚点地按输出序号硬贴。
```

**门**：

- 在 oracle100 + calib28 的 **94+27 格**上验证对齐正确率；
- 分母 = 全部可读格，未对齐/多字/空 = 错；
- **≥99%** 才可用于 verified 池；
- 不过门 → 退回“字数==格数才自动，其余全人工”；
- 人工预算按退回方案重算，不沿用 300–400。

### 3.5 回归与 canary

**回归门**：

- 新管线给 chosen 全行重贴标签；
- 旧标签来自已发布 v1.2.1；
- “旧对、新判错” = 回归；
- **回归容忍 = 0**；
- 所有回归格强制人工，判决写入 provenance 后才能改。

**canary**：

- R003（有→肩）
- R028（生→坐）
- R069（送→劍）
- R072（籩→邊，存疑，隔离）

新管线必须修正 R003/R028/R069 或送人工；R072 不得静默进真迹池。

## 6. 门

| 门 | 要求 |
|---|---|
| 行级对齐 | 94+27 全分母 **≥99%**；未对齐算错 |
| calib28 错标 | **≥21/23** |
| calib28 误报 | **≥3/4** |
| oracle100 | 全分母 **≥90%** |
| fresh holdout | 50–100 格 **≥90%** |
| verified 池抽检 | **≥99%**（分母=verified 格） |
| 回归 | **0 容忍**，全部人工 |
| canary | R003/R028/R069 必须修正或人工；R072 隔离 |
| 不可读 | 行图超长/渲染失败/非 JSON = 错；报告 attempt vs success |

“内容标签正确率 ≥95%”作废：94.7% 是现状，不是 goal；verified 池抽检 ≥99% 才是定义。

---

## 7. 坐标与数据口径

- 行框/格框：**300 dpi**；
- PP-OCR 字符框：**150 dpi**，与格框匹配时 ×2；
- 行裁剪：300 dpi，长边 ≤2400，只缩不放；
- 行图超长/空响应/非 JSON：算错，不静默排除；
- `verified` 池抽检分母必须写明。

## 10. 执行顺序

1. 4–5k 行定向补字符框；
2. 4–5k 行 VLM（DeepSeek 或本地 Paddle）；
3. DP 对齐验证（94+27，≥99%）；
4. 多见证 + canary + 回归；
5. 人工尾巴；
6. verified 池；
7. 修 `05/08/75`、val 300；
8. 才重训 v1.3。

一句话：**引擎给框，行 VLM 给全部 verified 行的字，DP 先过对齐门，人只裁分歧+回归+不可对齐。**

## 11. 99zf 结果与决策（2026-10-31）

`99zf` 在 128 格上跑通，读者为本地 PaddleOCR-VL 行级：

| 指标 | 数值 |
|---|---:|
| DP 单调性违例 | 0/128 |
| 三方 verified 精度 | 81/84 = 96.4% |
| 冲突 | 16 |
| 无对齐字符（拒贴） | 25 |
| 端到端全分母 | 81/121 = 66.9% |

结论：

1. **DP 单调性 0 违例只证明“没有倒序映射”，不证明“映射到正确的格”**；
2. 96.4% 的三方精度低于 99% 门，且 3 个错误全是**渗漏**（C006/C018/R061）；
3. 25 个拒贴里，R004 是完整的「所」，但 cell bbox 只有 103px、与 v6 框错位约 120px：
   这是**行尾格栅漂移**，不是 DP 错，也不是碎片；
4. 在线 DeepSeek 触发 `Authentication Fails (governor)`，本地 Paddle 是当前可用读者。

### 决策：选 A（拆门），但加三个前提

A 的定义不是“直接放行”，而是：

```
verified 精度 ≥99%（n≥500，不是 84）
+ 渗漏守卫：最近框中心不在格内/距离超阈值 → unaligned
+ 拒贴+冲突 ≤10%（约 530 格）；超过则先修几何，不硬贴
+ canary 3/3，回归 0
```

不接受“最近框”无条件补 25 个无框格：它们多数是行尾漂移，盲贴会把邻字渗进来。
若一轮工程后仍 >10%，退回 B（exact-length + 全人工），不拿 2,100 格硬扛。

B 的代价按 99zf 实测约 40% × 5,302 ≈ 2,100 格、1–2 周，只作为 A 失败后的兜底。
