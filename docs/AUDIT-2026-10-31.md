# C 线标签与训练失效专项审计（2026-10-31，第 6 轮）

> 范围：**C 线（永乐大典）** 的标签链、训练/评估链。动因是所有者的提问：
> 「C 线训练失败了几次：错标 6%+，越训真迹部分略进步、GAN 部分收敛不佳；A/B 有对照文本所以没这么严重。找出方法。」
> 方法：只读代码与文档 + 三组取证实验；关键结论经**三轮所有者抗辩**修订后冻结（§4）。
> 无 git 写操作；除本报告外未改仓库任何文件；实验产物在 /tmp（易失，复现命令见 §9）。
> 数字标注：**实测**=本轮亲手复算；**引用**=既有文档/审计/子代理走查，未二次复核。

---

## 0. 一句话结论

C 线训练失败的根因是**标签按行文本槽位序号分配、格内容零校验**，错标沿行传播且被人审低估；
而训练与评估的 val/参照全部取自同一污染池，测量失效使每次重训都不可决策。
本轮发现当前 OCR 栈原生支持**字符级框**（`return_single_char_box`，全仓库零使用），
实测把「行错位」类错标变成可自动检测的高精度判定；配合训练侧三处小修与四级验收门，
构成 v1.3 的 P0 路线。所有疗效数字在门过完之前不写进任何文档。

## 1. 为什么失败了几次才归因到这里（方法论反思）

| 结构性问题 | 后果 | 本轮对策 |
|---|---|---|
| **循环测量**：训练目标、val、页留出 clean、unseen 参照全部来自同一个 OCR 池 | 模型拟合污染目标时，所有指标同向失真，「越训越差」无法与「过拟合」区分 | 验证源必须独立：格级字符框三重一致 + 人工锚点，先修测量再重训 |
| **无 OCR 基准**：sentinel（99j）、VLM（99s）、聚类（99p）三个实验都没有先建人工真值基准 | 三个实验各花数天，产出全部无法解读（24.4%、37.2% 误报、锚点冲突 42.9%） | 先固化 1,272 格人工真值为 `ocr_bench`，任何 OCR 侧改动先过 bench |
| **聚合指标掩盖单字错误**：Dice/chamfer 与污染目标比，共同缺陷被奖励 | 聚合指标平坦甚至变好时，`一` 1,962 候选全错这类灾难不可见 | 逐字验收（500 常用字硬闸）+ 盲审双轨，聚合指标只作回归 |
| **原则漂移**：「有真迹尽量用真迹」没有质量闸语义，被读成「真迹计数神圣」 | 劣质真迹（模糊/缺笔/错标）挤占 GAN 的位置 | 所有者 2026-10-31 裁定：**合格真迹优先，劣质真迹降级并披露**（§5.1） |
| **统计口径事故**：本轮双方各出一次（Counter 冒充原字段；join 键 str/int 失配让 97 个坏格静默落空集） | 错误数字进入抗辩与门槛设计 | 统计口径三查纪律（§4.4），建议写入 AGENTS.md 常见坑 |

**概念框架（v1.3 的分诊基础）**：C 线错标分三类，修复手段互不替代——

| 类 | 例子 | 规模 | 修复轨道 |
|---|---|---|---|
| a. 系统性平移 | 行内一处并格/漏字，其后标签整体错位；`祗→若`、`一→萬` | 37.4% 行 nc≠nl（**引用** row_audit） | **字符框对位**（本轮主发现） |
| b. 几何缺陷 | 并格、空格、断格、灰条 | v3c 盲审 11.5%、v3d2 盲审 6.7% 的主体 | **v3d3 几何轨**（既有计划，不变） |
| c. 内容识别错 | 形近、异体、双引擎同错；`體` 格 | 人审几乎不可见（本轮测出通过格中 3.8%） | **AGREE_variant + 第三见证 + 人工桶** |

## 2. 根因链（全部有代码或数据证据）

### 2.1 [P0] 标签 = 行文本按槽位序号分配，格内容零校验

- `93_segment_c.py:277-285`：格的 `sub=k`（行文本 CJK 过滤后序号），`label=ch[k]`；`merged=False` 硬编码。
- `94_label_c.py:76-95,166-167`：双见证只在**行文本**上做 SequenceMatcher 对齐，
  格 k 继承行文本第 k 字。行级一致率 93% ≠ 格级正确率；37.4% 的行格数≠字数
  （406,419 格，**引用** row_audit.json），错位从第一个错点向后传播。
- 后果实例：`一` 的候选池系统性错位（§3.3 几何复现：79.7% 不可能有「一」的身形）。

### 2.2 [P0] 训练测量失效

- **valDice 每次只算 8 个样本**：`21_train_gan.py:283` `nval=min(8,len(val))`，每 5 轮一次；
  `_best.pt` 按它选（`:315-317`）——**快照选择基本是随机数**（实测+走查）。
- val 目标取自 pairs.npz（`:208`），与训练目标同源同污染。
- 页留出 clean 参照 = holdout 页上 `agree_ab ∧ ¬bad` 的格（`75_build_clean_c.py:66-67`，实测），
  PLAN-C-v1.3.0 §2.4 记载 clean 参照自身 32.9% 在嫌疑行；82 的崩坏率阈值 Dice<0.30
  （`82_eval_c.py:175,227`，实测）作用在污染参照上。

### 2.3 训练侧无抗噪机制，「越训越差」的数据侧归因

- G loss = L1×100 + adv + const×15（`21_train_gan.py:270-274`，实测），错标是硬目标；
  `--weight-complexity` 默认 0（**引用**走查），无样本加权/丢弃/截断。
- 旧 80 轮运行：页留出 ep20 **0.464** → ep50 **0.436**，崩坏 11.5%→17.4%（**引用** EXPERIMENTS-C E15）。
- v1.2.1 系列 90 轮（**引用**训练日志走查）：G loss 33.5→16.7 持续降、valDice 0.457→0.407 持续降、
  page200 与 unseen300 平坦——对含噪目标的拟合加深、泛化不涨，即「记住错格」的量化形态。

### 2.4 05_select 评分项奖励坏格

`05_select.py:171-183`（实测）：`score = d − 0.25·q − 0.15·m + 0.35·sz + 0.15·red`。
`q`（Laplacian 锐度）奖励碎边；`sz` 以同标签组内中位为基准，整组系统性错标时自适应、零保护
（`一` 全错则中位即错位格）。PLAN-C-v1.3.0 P0-2 已决定删 `q`，未实施。

### 2.5 a_only 单见证直接采信

`94_label_c.py:196-197`：无 B 行时单见证即标签。a_only 31,527 格（**引用** labeled.jsonl 统计）；
sentinel 实测错配率 46.3%（**引用** PLAN-C-v1.3.0 §P0-1.3）。

### 2.6 99s VLM 实验配置无效，不构成「视觉模型不行」的证据

`99s_vision_verify_c.py:44` 写死 `"detail":"low"`，模型名仅存环境变量未落盘（`:69-73`）。
结果：在 572 个**人工确认正确**的锚点上误报 37.2%（`vision_anchor572_compare.json`，实测读数；
match 62.8% / wrong 30.1% / fragment 7.2%），chosen 5,302 格 flagged 46.9%。
锚点误报样例（`區`「左半被切掉」）是 low detail 下小图不可读的典型表现。
结论：该实验判「配置无效」；重试必须整行输入 + detail high + 模型/温度落盘 + 先过 bench（§6 P2）。

## 3. 本轮新证据（全部本轮实测，可复现命令见 §9）

### 3.1 字符级框 API 可用，全仓库从未使用（决定性发现）

当前 RapidOCR 支持 `return_word_box=True, return_single_char_box=True`，逐行返回
`(字符, 逐字置信度, 四点框)`；在真实页面上验证竖排中文逐字成框、按 y 序正确推进
（義/聖/人/予/之/豈 每字一框）。`grep` 全仓库零使用。
这把「行文本→槽位序号」的位置分配问题变成「字符框↔格框」的几何匹配问题：**错不传播、每字带置信度**。

### 3.2 400 格对照实验：格级双见证的能力边界

设计：对 400 格人工审计样本（292 人审通过 + 108 已知坏格；其中 386 格能对上生产 cells.jsonl），
用 v6+v5 双引擎字符框做格级匹配（中心落格 ±5% 收缩、全框兜底；v5 走 prep_b 1.3×；
CJK 过滤），判定七类：AGREE / WRONG_LABEL / DISAGREE / HALF_AGREE / UNMATCHED / MULTI / NO_CELL。

| 层 | 结果 |
|---|---|
| 人审通过 289 格 | AGREE **206（71.3%）**；WRONG_LABEL **11（3.8%）**（双引擎一致读成别字）；其余不可自动判定 |
| 抽样目视 | 3/3 全是真错标：`祗→若`、`一→萬`（行错位）、`體` 格墨迹为 之/乏形（标签错成立；引擎读「足」也不对——WRONG_LABEL 语义是「标签错」，不是「OCR 对」） |
| 已知坏格 97 格 | 检出 48（**49.5%**）；分型：内容错位 3/7；并格 36/63 仍 AGREE；断格 7/16 AGREE |

读法（经所有者抗辩修订后的准确表述）：

1. 字符框匹配修的是 **a 类平移错标**，并给出 b/c 类的线索（MULTI/DISAGREE）；
   b 类几何缺陷的主体仍归 v3d3 轨道，两者互补，谁也不替代谁。
2. 人审盲审**系统性低估内容错**（盲审看不到标签，只能抓几何类）——现有 6.7%/11.5%
   基线不覆盖 c 类；内容错的真实基线要靠带标签盲审重测。
3. 3/3 目视只证明方向，不证明精确率；WRONG_LABEL precision 的正式门槛是 §5.2 的四级门。

### 3.3 「一」池的几何复现（与 OCR 无关的独立证据）

生产 cells.jsonl 中 1,199 个标「一」的格：宽高比中位 **1.42**；
**79.7% 落在 0.4–2.5（方块字身形，几何上不可能是「一」）**，仅 19.9% ≥2.5。
v3c 重切未解决池级系统性污染——这不是切格噪声，是 2.1 的分配机制问题。

### 3.4 成本实测与排期口径

366 页 / 804 s / 双引擎 / 单进程 / 热缓存 = **2.2 s/页**；外推 3,428 页全量约 **2.1 h 单进程**，
6 worker 约 25 分钟。此为会话内实测、未落盘成脚本，**按 PLAN-C-CLUSTER 的规则不得直接用于排期**；
正式排期前先把 bench 脚本化并复测（含 6 worker 扩展性）。
对比：PLAN-C-CLUSTER 按「逐格 OCR 2.23 格/s」估全量 296 h——字符框方案把成本模型降了两个数量级，
且**几何完全不动、只重推标签**，不触发「全量重切 40 min+16G×7 次」的老坑。

## 4. 三轮抗辩与裁决记录（过程存档）

> 所有者的三轮抗辩实质提高了结论质量；记录在此防止未来会话重新争论。

### 4.1 第一轮：疗效承诺（所有者抗辩成立）

| 原报告表述 | 抗辩理由 | 裁决 |
|---|---|---|
| 错标压到 <2% | 3.8% 本身 >2%；3/3 目视 CI 30–100% 不能证明精确率 | 撤回数字，改四级门（§5.2） |
| 字符框是「根因解」 | 修的是位置不是认字；并格 36/63 仍 AGREE | 降格为「a 类平移的解」，与 v3d3 互补 |
| 25 分钟 | 未落盘、只是 OCR 单环节下限 | 降格为测量点（§3.4），全链 3–5 天机器+2–3 天人工（估计值） |
| 「每字平均 190 样本」 | 拿平均当保证 | 撤回，改逐字分布（§5.3） |

### 4.2 第二轮：真迹优先原则（所有者裁定）

抗辩方主张「丢 WRONG_LABEL 伤覆盖、回落 GAN 是损失」；所有者裁定：**「有真迹尽量用真迹」
是最早的原则，但劣质真迹（模糊/缺笔/错标）不如 GAN，且 A/B 已验证 GAN 在 80/90 轮的质量**。
裁决采纳，三处先例背书：

- C/E15：15 个 Dice<0.10/墨量<0.2 的真迹剔除改 GAN（5,310→5,287），发布无异议；
- v3d3 方案：ambiguous 格从 chosen 移除走 GAN/ribbon，不保留错误真迹；
- C/E12：GAN ep30 干净集 chamfer **6.82** 已低于真迹互比地板 **6.98**。

### 4.3 第三轮：口径之争（双方各错一次，均以复算收口）

- 抗辩方称 `chosen.n_samples` 全 1，断言我方长尾表不可能来自该字段。
  复核：三份 chosen.jsonl 无一全 1（min 1 / median 22 / p90 403–404 / max 27,427）；
  抗辩方自查发现把「每字在 chosen 的行数」当成了 n_samples（Counter 冒充原字段），撤回。
  但**口径主张成立**：n_samples 是 prefer-ab/prefer-clean 过滤后的选优池大小，
  与逐字 AGREE 数在 3,418/5,302 字上不等，不得用作覆盖口径。
- 逐字 AGREE 分布以 `labeled.jsonl` 重算，两法一致（±1）：
  0/1/≤2/≤3 = **266/175/791/1,051**，median 23，p10 2，p25 5，覆盖 **95.0%**。
- ±1 机制定位（修正双方此前的解释）：差异全部在 **亙**——16 个格
  `label_src='relabeled_mismatch'`，v6=v5=亘（改标前一致），96 把标签 亘→亙 后
  `agree_ab` 未失效（过期布尔）。双方原先的解释（out_of_block / label 清空）都不成立。
  按冻结规则这些格属 **AGREE_variant**（双引擎一致 + 人工策展等价），是合法证据但不是 ab。
  严格尺 zero-AGREE=266（覆盖 95.0%），P0 尺（ab ∪ 策展等价）=265；人工桶下限维持 266。

### 4.4 事故日志 → 统计口径三查（建议写入 AGENTS.md 常见坑）

1. （抗辩方）派生 Counter 冒充原字段 → 统计前先 `print(field, type, min, max, n_unique)`。
2. （审计方）join 键 str/int 失配，97 个已知坏格静默全落「未标记」层，首版输出 `MARKED n=0`
   未触发警觉 → 分组结果出现空集或全同值先查 join 键，再解读。
3. （审计方）±1 级差异先用 plausible 解释直接写进结论（out_of_block 之误）→
   必须定位到具体记录再解释机制。
4. 附：p90 403 vs 404 为分位数估计法差异（numpy 线性插值 vs 序数索引）；bench 脚本须冻结估计器。

## 5. 冻结决策与验收门（v1.3 P0，所有者 2026-10-31 确认）

### 5.1 原则修订（待登记进 AGENTS.md，见 §8）

- 「有真迹尽量用真迹」修订为：**合格真迹优先；真迹未过质量闸（87 号：Dice vs 文楷、墨量）
  或标签未过验证时，降级 GAN/ribbon，并在降级登记表与发布说明披露计数。**
- **码位跟墨迹**：异体/繁简等价只用于验证（AGREE_variant），服务的码位 = 墨迹实际所示变体；
  禁止把 target 改写成 OCR 归一化读法（`爲` 的墨迹永远生成在 `爲` 的码位）。
  先例：96 的 relabel 规则 亘→亙、E15 的 个→個。
- 降级登记表建议 `work-c/real_rejected.jsonl`（字段：file/char/reason/verdict），
  provenance 三态不变（shipped 态照旧记 gan/base）。

### 5.2 四级验收门 + 执行约束

1. **WRONG_LABEL precision ≥90%**：50–100 格，按行错位/形近/异体/大字头分层盲抽，遮标裁决。
2. **AGREE precision：100 格二次盲审内容错 ≤2**（auto-pass 池是训练主体，此条最要害）。
3. **覆盖终态门：格级 AGREE ⊕ 人工确认 ≥97%**；过程指标另报「纯自动格级覆盖」。
   注意尺子：95.0% 是**行级旧尺**基线，格级尺更严，切换初期纯自动覆盖必然低于 95%，
   不得与终态门直接比大小。
4. **chosen 内容错标率相对下降 ≥50%**：基线由新旧两轮盲审重测（带标签盲审），不沿用 6.7%。
5. 约束：疗效数字在 1–4 过完前不进任何文档；v1.2.1 冻结不动；不全量重切；
   人工桶下限 266 字（zero-AGREE 全集，含总样本 ≤2 的 98 个最弱字优先），
   上限 = 266 + 175（single-AGREE 被 WRONG_LABEL 命中的召回依赖）。

## 6. 行动清单

**P0-A 字符框对位层（结构性修复，估算 3–5 天机器 + 2–3 天人工，bench 落盘后再冻结排期）**

1. `92_ocr_c.py` 两引擎加 `return_word_box+return_single_char_box`，逐字框+置信度落盘一张表；
2. 新写匹配器（中心落格→IoU 兜底），产出七类判定 + 置信度；

### 16.2 实验 B：行上下文转写——**同一模型，83.9% → 98.7%**

方法：整行图像（300 dpi 原生、非单格）让模型转写全行，按切格位置取读数。

### 16.3 含义

1. **同一模型换个问法，83.9% → 98.7%**：瓶颈从来不是模型识字量，是「单格孤立判读」这个
   任务设定。gate 当初拦下的不是模型，是问法。
2. 生产验证器形态：**行级转写 + DP 对齐（允许增删）→ 对齐格多见证自动验证；
   nc≠nl / 对不上的格 → 隔离**。gate 需按行级口径重新定义（所有者决策）。
3. 不可机判尾巴（R003/R063 类，约 2%）仍归人工——但那是每百格 2 格，不是每格都靠人眼。
4. 成本：行级转写约每行 1 次调用，chosen+候选规模约 6–8k 行，DeepSeek 计价约 **6–10 元**。
5. 产物：`oracle100_linectx.jsonl`、`pages300/`、`vlm_crops300/`。

## 33. 补记二十三（11-01，44 字逐字归因：holdout→min-samples 44/44 零未解释）

对所有者「只有 24 个旧 chosen 格在 holdout 页」的对账：**量的是不同东西**。
丢弃机制 = post-holdout 样本数 < min-samples(2)（计数不足），不是 chosen 格的位置。
逐字归因（pre 样本 / holdout 页样本 / bad / ab / 非 holdout 剩余）：

**44/44 = holdout→min-samples，零未解释。**
- 42 字：非 holdout 剩余 1（<2 丢弃）
- 2 字（岍/蕢）：非 holdout 剩余 0（全部在 holdout 页）
- bad 标记：仅 3 字有 1 个 bad（畬/膈/襚），不改变归因

所有者查的「旧 chosen 格在 holdout 页」只有 24 个——正确，但不构成矛盾：
一格不在 holdout 页的字，仍会因**其他格**进 holdout 导致 post-holdout 计数
跌破 min-samples 而被丢。两个度量互补，不矛盾。

**44 字丢失的账目闭合：holdout 纪律（61,188 行排除）→ 44 字 post-holdout < 2 → 丢弃。**
零未解释，v1.3 重训解锁维持。
