## C/E1 语料普查：3,538 页，全部 300 dpi

**目的**：确定工作分辨率、页面分类、红栏几何。此前只有零散几页的目测。

**配置**：`scripts/91_render_c.py`（150 dpi 渲染 + 红栏纠偏）+ `91b_recensus_c.py`。

**结果**

| 项 | 值 |
|---|---|
| PDF / 页 | 41 / 3,538 |
| 文字页（有可用红栏） | **3,428** |
| 无栏/地图/衬页 | 104 |
| 封面 | 6 |
| `eff_dpi` | **3,428 页全为 300** |
| 红栏宽 @150dpi | 中位 268.5，p10 216，p90 327.5 |
| 纠偏角 | 中位 0.158°，最大 1.2° |

**结论**

1. **“532 页只有 245 dpi”不成立**：逐页量 `eff_dpi`，全部 300。工作分辨率统一定 300 dpi，
   小字双行的一格约 180–260 px，与 A 线同量级。
2. 104 页无栏页（地图、衬页）直接跳过，不进 OCR。**这是正确的**：例如卷10949 的
   《江西地圖》页有 5% 墨迹但没有任何栏线，硬切只会得到碎片。

**复现**：`python3 scripts/91_render_c.py --workers 6 && python3 scripts/91b_recensus_c.py --workers 6`

## C/E2 红栏检测：自相关取基频，否则每隔一条线丢失

**问题**：初版 `_autocorr_pitch` 取 [lo,hi] 内的全局最大峰，遇到「奇偶线深浅交替」的页
（如 p00_0017、p01_0018）会锁到 **2× 周期**，随后把真实线当成“双线”合并，整页只剩 2–3 条线。

**修改**：在 [lo,hi] 内取**最小的、达到最大值 78% 的局部极大**（基频优先）；
合并阈值 0.55→0.30；峰阈值 0.12max→0.10max。

**结果**

| 页 | 修前线数 | 修后线数 | 修前 pitch | 修后 pitch |
|---|---|---|---|---|
| p00_0017 | 2 | **10** | 548 | **272** |
| p01_0018 | 3 | **9** | 431 | **215** |
| p00_0005 | 9 | 9 | 266.5 | 266.5 |

**结论**：红栏是这批语料唯一可靠的几何基准；基频优先是必要的，不是调参偏好。
**副作用**：仍有 7–8 页 pitch>1200（版面散乱），切字阶段用「OCR 行宽 / 栏距」比值把它们挡掉。

## C/E3 双引擎 OCR：字符一致率 91.1%（前 541 页抽样 89.5%）

**配置**：
- 见证 A：PP-OCRv6 small，彩色纠偏图 150 dpi；
- 见证 B：PP-OCRv5 mobile，去红 + 2–98% 拉伸 + 1.3× 放大。

**指标**（541 页、10,736 行、194,396 字）：

| 指标 | 值 |
|---|---|
| 行匹配率（IoU>0.25） | 90.2% |
| **字符一致率（一致字 / A 的字数）** | **89.46%** |
| A 行置信度 p5 / p10 / 中位 | 0.771 / 0.892 / 0.973 |

**结论**：两引擎差异足够大，可以作为「一致才给标签」的闸门；不一致约 9–10%，全部置空。

**全量结果**（3,428 页）：58,771 行 / **1,297,735 字**；行匹配 54,829/58,771（93.3%）；
**逐字一致 91.1%**；唯一汉字 6,864；最终 1,003,986 格拿到标签。
**注意**：若改成只记录 `equal` 块，`conflict` 永远不会触发（初版 bug，已修）——
必须把等长的 `replace` 块也映射成 B 的读法，才是真正的“不一致”。

## C/E4 双行/单行判据：只看白走廊会把单行字切成两半

**问题**：早期用「栏内中央 26–74% 的最白列」判双行。卷10949 的《建置沿革》页是**单行**，
但文字偏在栏的一侧，中央存在白走廊 → 每一栏都被判成双行，每个字被切一半
（实测该页 419 格，其中约一半是半字）。

**修改**：加“两侧墨量平衡”判据——左右两半的墨量比需 ≥0.30，否则判单行。

**结果**：该页仍是双行（复查发现它确实是双行，只是行距大），但判据保留：
真正单行的页（卷10949 地图页等）不再被切开。

**结论**：单/双行不能只看白走廊，必须要求两侧都有相当墨量。

## C/E5 墨迹阈值：固定百分位吃掉笔锋，改「Otsu + 纸面相对限幅」

**指标**：同一批训练对上的 `book_ink / WenKai_ink` 中位数。

| 阈值 | 墨量比中位 | 观感 |
|---|---|---|
| `p2 + 0.34·(p50−p2)` | 0.539 | 笔画毛糙、时有断笔 |
| `p2 + 0.44` | 0.57 | 略好 |
| **Otsu，限幅在 `p2+[0.42,0.62]·span`** | **0.629** | 笔画连续，接近原墨 |

**结论**：这批扫描的笔画边缘灰阶跨度大，固定百分位会削掉边缘；Otsu 的绝对阈值在
“墨少”的叶上会漂，限幅解决漂移。三者都在同一页上复核过。

**注意**：墨量比 0.63 明显低于 B 的 0.714、A 的 0.824——这是**书手用笔细**，不是阈值问题。

## C/E6 切字：组件归属 + DP 切分

**做法**：
1. OCR 行框定行（大字行宽≈整栏、小字行宽≈半栏）；
2. 行内按 OCR 字数 N 用 DP 在低墨行切格；
3. 全页连通域按质心+重叠两遍归到格，格子 mask **只取本格组件**（不裁矩形）。

**结果**（4 页抽检，1,437 格）：`bad` 率 6.5%，`edge` 中位 0.000（切在空白行）。

**否定结论**：直接裁 `slot` 矩形会把上下邻字的笔画带进来（在「一」格里看到一个下一字的
起笔），必须组件归属。

## C/E8 GAN 训练：5,310 对，原计划 60 轮（实际停在 ep30，见 E12）

**配置**（与 A/B 同一配方，只换数据）

|---|---|

| 网络 | zi2zi U-Net + 5 层 PatchGAN + hinge + 增强（±2°/±3px/0.95–1.05） |

| 设备 | MPS；每轮 **499–516 s**（332 step） |
| 快照 | 每 10 轮 + 验证最佳 |

**训练集特征**（与 A/B 的关键差异）：目标墨量只有文楷的 **0.592**（A 0.824 / B 0.714），
即这批写本用笔更细；`ink ratio = 38.73 · comp^-0.430`。

**ep10 体检**（干净集 200 字，close 2，含阈值扫描）

| thr | Dice | 墨量比 | 崩坏率 |
|---|---|---|---|
| **−0.30** | **0.413** | **1.001** | 16.0% |
| −0.10 | 0.406 | 0.950 | 18.0% |
| 0 | 0.403 | 0.926 | 18.0% |
| +0.30 | 0.391 | 0.854 | 20.0% |

**读法**：ep10 的墨量=1.00 工作点在 **−0.30**（不是 A 的 −0.05，也不是 B 的 −0.10）。
后处理一变工作点就漂，必须每个检查点各自扫——这条在 C 上再次成立。

**负结果**：`valDice` 在 ep1/5/10 为 0.267 / 0.348 / 0.431，仍在上升；
「早停」在 C 上没有依据，至少不能按 B 的 ep20 见顶来套。

## C/E9 带状扫掠回退在 C 上明显更差：尽量少用

同一批干净集（80 字）上扫 ribbon 的 scale 倍数：

| scale 倍数 | Dice | 墨量比 | 崩坏率 |
|---|---|---|---|
| 0.9 | 0.274 | 0.937 | 66% |
| 1.0（按 C 曲线标定） | 0.287 | 1.031 | 61% |
| 1.1 | 0.298 | 1.124 | 50% |
| 1.25 | 0.312 | 1.264 | 40% |
| 1.4 | 0.324 | 1.406 | 35% |

对比 B 线同口径（ep20）崩坏率 20.5%。**C 的笔画太细**，带状扫掠在 256 px 下容易断笔，
提高 scale 只能把断笔变粗，不能变连。

**结论**：C 线的回退守卫要**放宽**（少回退），宁可让 GAN 输出带一点噪声，也不要用
ribbon 的断笔。回退只用于 GAN 输出为空/明显崩坏的字。具体工作点见 E10。

## C/E11 干净集的结构：按页留出仍是“见过的字、没见过的样本”

留出 207 页（6%），得到干净集 **3,213 字**；其中只有 **44 字**是训练集里没有的字
（5,310 个真迹字覆盖了绝大部分常见字）。所以：

- 3,213 字的指标衡量的是**风格迁移**（同字、不同样本），不是生字泛化；
- 44 个生字样本太小，不能单独下结论。

这是「按页留出 + 全量收字」的必然结果，写进发布说明，避免把 Dice 读成“生字准确率”。

**真迹互比 chamfer 地板 = 6.98**（同字两真迹样本，n=800）——比 A 的 5.16、B 的 3.57 都高，
说明这批写本的**同一字在不同页的写法差异本来就大**（多人分抄）。所有 chamfer 数字都要
对着这个地板读。

## C/E13 生成标定：字重偏重 21% → 1.108（v1.0.0 口径；v1.0.1 见 E15）

**问题**：首次全量生成（thr +0.10, close 3, blend 1.0）字体级验收 **weight_bias 1.212**，
超出 0.90–1.15 的闸门。合成字/文楷 0.729，真迹 0.601。

**标定**（200 个随机非真迹字，24 组配置，字体级渲染口径）：

| thr | close | blend | synth/wk |
|---|---|---|---|
| 0.10 | 3 | 1.0 | 0.736（首版） |
| 0.20 | 0 | 0.8 | 0.684 |
| 0.30 | 0 | 0.8 | **0.662** |
| 0.40 | 0 | 1.0 | 0.664 |

**采用 thr +0.30、close 1、blend 0.8**：
- blend 0.8 与真迹的 `06_norm` 一致（训练目标也是 0.8），不再做第二次归一化；
- 字体级 weight_bias **1.108**；字号扫描 12px 0.907 / 16px 0.957 / 24px 1.044 / 48px 1.022；
- bbox 宽比 1.041；合成字重心 dx +0.96% dy +1.05% em；
- 回退率 300/15,682 = **1.9%**（守卫 `ink∈[0.42,1.20]`、`comp-tol 6`）。

**代价**：阈值提高后崩坏率从 13% 略升（干净集口径），但字重与真迹一致；
两者取字重，因为混排时字重差是最先被看出来的。

## C/E15 v1.0.1：质量修复（回应「看起来很糙」）

**反馈**（2026-10-28）：字体预览里字重忽粗忽细、边缘毛糙；部分简体码位显示成繁体字形；
训练轮数不足。

**诊断与修复**

| 问题 | 证据 | 修复 |
|---|---|---|
| 字重跳变 | 同字体逐字墨量/文楷比 **0.42–0.98**（援 0.42、上 0.98） | 逐字按 C 线墨量曲线 `ink = 39.4·wenkai^-0.432` 标定（距离变换做亚像素膨胀/腐蚀，`--ink-gain 1.10`）。真迹收窄到 **p5 0.85 / 中位 0.99 / p95 1.14**；字体级 16/24/48px 偏差 **0.959 / 1.008 / 0.991** |
| 纸屑毛边 | 300 dpi 纸纹、墨点被 potrace 原样带入 | 追踪前去噪（按面积比例删小连通域、填针孔、中值平滑）；`turdsize 2→3`、`alphamax 0.4`。去噪之后 turdsize 只需挡 1–2 px 灰尘 |
| 简体码位配繁体字形 | `书→書、习→習、长→長、价→價、礼→禮、类→類、庄→莊` 等 10 个（训练目标 vs 文楷简/繁渲染的 Dice 差，取 margin>0.03） | 7 个丢弃（繁体码位本来就在真迹集）、3 个重标（个→個、亘→亙、坛→罎）；真迹 5,310→**5,303**。修复脚本 `scripts/96_fix_labels_c.py`（在 94 与 05 之间运行，幂等） |
| 孔洞丢失 | v1.0.0 全字体 5.6%、真迹 11.2% | 把 `repair_counters` 挪到字重标定**之前**（标定会先腐蚀/膨胀，之后补孔会失败），加 `min_hole_area=6` 忽略 2 px 针孔、允许加大核最多 +22% 墨量。**全字体 lost 0.9%、真迹 4.3%**（v1.0.0 为 5.6% / 11.2%）；早期 ep30 构建曾到 0.5%，重生成后为 0.9%，仍在同一量级 |
| 训练轮数 | 旧版停在 ep30，而 B 线实际是 80 轮（加权实验 100 轮） | 清理数据后从零重训（5,303 对，每轮约 500 s）。**实测 ep20 最好，之后结构指标单调变差**，见下面的检查点表；训练在 ep52 停止（计划 80 轮，证据足以定夺） |
| 真迹碎片 | 15 个字（纂/鑑/輯/覽/毓…）在 `87_check_choices` 里与文楷 Dice<0.10、墨量 <0.2；`罎` 的源格是「云」 | 全部剔除，改由 GAN 生成（`77 --only`）；`個` 的源格是「个」，标签改回 `个`。真迹 5,303→**5,287**；这 16 个字在 C-Real 中不再有字形（Real 只含真迹） |

**检查点选择（207 页留出集，n=800，`82_eval_c.py`）**

| 检查点 | Dice | chamfer | 崩坏率 | 墨量（未归一化） |
|---|---|---|---|---|
| **ep20** | **0.464** | **6.61** | **11.5%** | 1.184 |
| **ep30（选用）** | 0.444 | 6.64 | 15.4% | 1.037 |
| ep40 | 0.444 | 6.57 | 15.4% | 1.059 |
| ep50 | 0.436 | 6.63 | 17.4% | 0.988 |

越训越差：Dice 单调下降、崩坏率 11.5%→17.4%；墨量（未做逐字标定）倒是靠近 1，但生产管线本来就会逐字标定。

**取舍**：ep20 结构最好，但把 ep20 的生成结果送进生产管线（thr 0.30 / close 1 / 去噪 / 逐字墨量标定）后，
字体级字重比 **1.19**，超出 0.90–1.15 的硬闸；把 gain 从 1.10 压到 0.99 也没有改善
（掩膜面积标定在 ep20 的字形上收敛不到目标）。ep30 的未标定墨量已接近 1（1.037），
标定后字体级偏差 **0.959 / 1.008 / 0.991**，全项过闸。所以 v1.0.1 用 **ep30**。

**简体字的结构守卫**：`简/鸟/档/标` 这类「简体码位没有真迹、由 GAN 生成」的字，
模型会按繁体训练目标的分布把它写成繁体（简→簡、鸟→鳥）。抽 200 个简体码位，组件数差 >2 的
触发率：**ep20 17.0% → ep40 23.5%**（轮数增加没有降低，反而略升）。三向对照
（`work-c/cmp_simp.py`）显示触发字是系统性偏旁繁体化（纟→糹、鱼→魚、页→頁、钅→金），
不是计数噪声。`77_generate_c.py --struct-guard` 对这类字回落到 ribbon（保结构、骨架取自文楷），
全字体 ribbon 占 **1,228 字 / 7.8%**（v1.0.0 是 300 / 1.9%）。风格上比 GAN 字平，但结构正确。
