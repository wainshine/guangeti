# C 线 v3d2 并格拆分方案（含起因、经过、失败教训）

> 2026-10-30。当前最好切分是 **v3d2**（300 格盲审 20/300 = **6.7%**），
> 其中主要残留是“一格两字/三字”和少量灰条/缺笔画。下一步只在 v3d2 上打补丁，
> **不再全量重切**。目标 **≤5%**，最终构建自动带 P1 修复与 42 码位标点。

---

## 1. 起因

- v1.2.0 只是**本地打包**，没有提交仓库；后面的轮次是探索，目标是找一个质量更好的版本作为 1.2.0。
- 用户对 8 张评审图逐格标注后，暴露出 `一` 竖块、`申/昌` 错位、`四` 碎边、`串=尚`、`类=禁`、`图=図` 等；
- 400 格盲审（v3c）**108/400 标记**，uniform **23/200 = 11.5%**；类型：
  **并格 63 / 空 22 / 内容错位 7 / 断格 16**；并格+空 = **78.7%**。
- 结论：一号根因是**行级 OCR 序列标签逐格分配、格内容零校验**；第二位才是选优和生成。
- 后续切分实验：
  - v3d（center-gate + gap-mid）：merged 20→6（10 页）/ 33→16（20 页），300 格 **9.3%**；
  - v3d2（再加 merge-trim，center-frac 0.12）：merged 16→1（20 页），300 格 **6.7%**；
  - 用户复核 v3d2 的 300 格，确认**比 v3d 好**；我此前用 Dice/chamfer 判“更差”是拿错了尺子。

## 3. 失败教训（必须写进流程）

1. **每改一处就全量重切**：一次 40 分钟 + 16G + 240 万文件；共 7 份全量、137G、1,667 万文件。
   → 以后只打补丁/页级 diff，保留 top 3（v3d2、v3d、v3c），失败实验删数据。
2. **top-10 在污染池里没有用**：`一` 的 1,962 个候选 10/10 是“上字+横”；top-10 只能否决，不能造字。
   → 先控制（93 格框 + 行哨兵/几何），再谈 top-10。
3. **OCR 不能当硬否决**：same_wrong precision 52%、different 24%、read_back 仍有 6.7% 切错；
   → 只做复核排序，不做准入闸。
4. **merge-trim 用“丢字”换指标**：merged 16→1，但 Dice/崩坏变差；用户看切分质量，不是 Dice。
   → 并格要**拆分**，不是丢弃。
5. **指标与审计测的不是一件事**：Dice/chamfer 与 C 自身污染目标比；单字对错要靠盲审/逐字看。
6. **93 的 merged 在组件归属前按整槽算**：约 19% “merged”只有一条墨带（如 `千`），被 `--prefer-clean` 降权；
   → 判定必须在归属后按实际 mask 做（已修）。
7. **`render_base` 用的是 256px 字体对象**：只改画布/帧尺寸不够，455 字仍 0.66×；
   → 掩膜和帧必须同时用目标分辨率字体（已修，`图` 128×146→194×223 px）。
8. **先打包后改 stats/provenance**：zip 哈希改了三次；
   → 先冻结 stats/provenance，再打包。
9. **口径不冻结就排期**：37.4% vs 60.7% 是 `li` 是否 dedupe 后的 join 语义；60.7% 是幻影。
   → 所有比例必须带定义/文件/列。

## 4. 下一步：v3d2 并格拆分（v3d3）

### 4.1 基线

- 输入：`work-c/exp/v3d2/{cells,masks,cells.jsonl,labeled.jsonl,chosen.jsonl,norm.json,pairs...}`；
- 基线错标率 **6.7%（20/300）**；只改被标记/几何异常的**行**，其余格原样保留；
- 不跑 93 全量，不重切未涉及页。

### 4.2 目标清单

1. **2/3 字并格**：一格内有 K≥2 个 y 墨簇；按 y 投影谷拆成 K 格；
2. **灰条/栏线格**（如 #199）：`w/h` 极端、mask 细长且无字；直接标空/丢弃；
3. **缺笔画**：两类都要覆盖——被中心门控排除的、被 merge-trim 误剪的；
   用两遍归属判据（组件面积与本格 slot 重叠 ≥45–50%），不能只看 bbox 相交；
4. **不碰**：已正确的格、未标记的行。

### 4.3 算法（行级补丁，不重切页）

对每个含嫌疑格的行 `(key, li)`：

1. 取该行所有 cells（按 `sub` 排序）；**墨源用 v3d 的 `masks/`，不是 v3d2 的**：
   v3d2 的 merge-trim 已把并格第二字从掩膜剪掉，在 v3d2 掩膜上做 y 投影永远只看到 1 簇；
2. 对每个 cell 在 **v3d mask** 上做 y 投影，找墨簇 `runs`；候选高度用 **v3d 的 slot 高**（v3d2 的 bbox 高已被 trim 缩短）；
3. 若 `len(runs) >= 2` 且 `slot_h > 1.1·cpitch`：
   - 在相邻 `runs` 之间找最大谷，切成 K 段；
   - 用行文本 `ch[sub .. sub+K-1]` 作为 K 个标签；
   - 若相邻 `sub+1..sub+K-1` 已有空/低墨格，**消费空槽**；没有空槽则只保留主簇并标记 `overflow`（不硬造标签）；
   - 新格文件名沿用 `key_c.._l.._s{sub+j:03d}.png`；原合并格删除；
4. 若 `len(runs)==1` 但 `h>1.3·cpitch`：按上下留白裁到 bbox，避免带上一字残笔；
5. 灰条：`w < 0.15·cpitch` 或 `h > 2.0·cpitch` 或 mask 的 ink 沿 y 连续且宽度 <3px → 标 `drop`；
6. 缺笔画：对 `chosen` 中 mask 的组件 bbox 与主 bbox 相交但质心在中心门控外的组件，补回（只对该字，不改其他格）。

### 4.4 行文本对齐（关键）

- 标签仍用 `94` 的行文本 `ch[k]`；拆分后的 K 格必须落在 `sub..sub+K-1` 的连续槽位；
- 若 K 超过剩余槽位/与已有非空格冲突，**不拆**，保留原格并标 `overflow`，进人工清单；
- 这样不会因为拆格造成新的整体错位。

### 4.4.1 20 页探针与“拆/剪都不靠谱”的实测（2026-10-30）

`scripts/99m_probe_split_c.py` 在 20 页上对比 v3d2/v3d 掩膜：

```
no_ink_cell          33
trim_hides_second    37   ← v3d2 只剩 1 簇、v3d 有 ≥2 簇，正是 trim 剪掉的第二字
candidate            29   ← v3d 上可直接看到 ≥2 簇
cluster_too_small     7
valley_too_narrow     1
```

**结论 1**：拆分必须用 **v3d 掩膜**；v3d2 掩膜上 37 个格永远拆不动。

**结论 2（更要紧）**：这 37 个格里，**相邻槽位几乎都被占用**（20 页 29 个候选中 21 个 `free=False`），
不是“空槽+两字”，而是“本格两字，下一格也有字”。所以**不能按空槽拆分**——拆了会覆盖下一格、整体错位。

**结论 3**：退而求其次的“trim 到主簇”也不可靠：
- 按高度选主簇：20 个里约一半选到邻居（`心`→`人`、`民`→`州`、`以`→`後`）；
- 按 WenKai 标签 Dice 选：20 个里仍有约一半错（`優`→`丁`、`友`→`且`、`文`→`房`、`台`→`天`、`自`→`知`、`曰`→`語`、`少`→`則`）。
- 单格 OCR 也不可靠（前文：precision 52%/24%）。

**因此 v3d3 不应“硬拆/硬剪”**：对“本格两字且下一格非空”的格，可靠做法是
**标记 `ambiguous` 并从 chosen 移除**，该字走 GAN/ribbon；不保留错误真迹。
代价是真实覆盖率下降（约 6.7% 的候选），收益是切分错标率归零。

### 4.5 验收

1. **20 页先验**：与 v3d2 同页对比，merged 数、断格数、标签漂移（应 0）；鮓/渤/串 回归；
2. **全量补丁**：只写改动的行；产出 `work-c/exp/v3d3/`，其余格硬链/复制 v3d2；
3. **300 格盲审**：同一抽样协议，目标 **≤5%**；若 >5%，只继续修被标记的类型，不再全量；
4. **最终构建**：`77`（P1 已修）+ `79`（自动 42 码位）→ 80/84/83/97 → 包；
5. **before/after**：v3d2 的 300 格与 v3d3 的 300 格同协议对比，记录类型变化。

### 4.6 停止线

- 20 页样本 merged 不降或标签漂移 >0.1% → 停止，回到 93 行带切分；
- 300 格 >5% → 不进入最终构建，继续只修被标记的行；
- 任何一步不得全量重切。
