# 发布说明：GuanGe Kai C v1.0.1

> 2026-10-28。C 线质量修复版，接替 v1.0.0。
> 逐字来源、覆盖表、校验和见 `release-c/`。
>
> **三线同步发版**：A 线 **GuanGe Kai v1.7.0**、B 线 **GuanGe Kai B v1.2.2**、
> C 线 **GuanGe Kai C v1.0.1** 同批发布（2026-10-28）。C 线自身的字体与校验和见 §6；
> A/B 两线的完整性由各自发布流程验证，C 线不再代为声明其哈希。

---

## 1. 一句话

v1.0.1 修掉 v1.0.0 的三类观感问题：**字重忽粗忽细**（多抄手 + 单样本）、
**边缘毛糙**（扫描纸屑被原样追踪）、**简体码位显示成繁体字形**（10 个错配标签）。
真迹 **5,303 字**（基本区 25.26%），GAN 14,461 字 + 带状回退 1,228 字，覆盖 20,992 字。
字体文件同时从 20.6 MB 降到 **15 MB**。

## 3. 改了什么

| 问题 | v1.0.0 | v1.0.1 |
|---|---|---|
| 逐字字重（墨量/文楷比） | **0.42–0.98**（多抄手，每字一个样本） | 逐字按 C 线墨量曲线标定，**0.85–1.14** |
| 字体级字重偏差（16/24/48px） | 1.108 | **0.974 / 0.969 / 1.025 / 0.995** |
| 全字体孔洞丢失 | 5.6% | **0.9%** |
| 真迹孔洞丢失 | 11.2% | **4.3%** |
| 简体码位错配 | 书→書、习→習、长→長、价→價、礼→禮、类→類、庄→莊 等 10 个 | 丢弃 7 个、重标 3 个；简体码位加结构守衛（组件数差 >2 回落 ribbon） |
| 训练轮数 | ep30（未比较） | 清理后从零重训，训到 ep52；**逐检查点比较后仍选 ep30**（ep20 结构最好但字重 1.19 过不了闸，ep30–50 结构单调变差） |
| 轮廓复杂度 | 20.6 MB | **15 MB** |

具体做法见 `docs/EXPERIMENTS-C.md` C/E15：
追踪前去噪（删小连通域、填针孔、中值平滑，`turdsize 3`）；
逐字墨量标定（距离变换亚像素膨胀/腐蚀，目标曲线 `ink = 39.4·wenkai^-0.432`）；
`repair_counters` 移到字重标定之前并加面积过滤（2 px 针孔不算字碗）；
简体码位结构守衛 `--struct-guard`。

干净集两行是 **模型级指标**：`82_eval_c.py` 在 `thr 0.0 / close 2` 下测，**不套用**生产管线的
追踪前去噪、逐字墨量标定与结构守衛，因此不等于最终字形的质量；同一评估的**崩坏率 15.4%**
（ep30，n=800；ep40/50 为 15.4%/17.4%）也未作为发布闸门。生产工作点见 §3。

## 5. 已知限制

1. **标签来自双引擎一致，未经逐字人工校对。** 与 A/B 最大的差别；
   两引擎同错的形近字（曰/日、己/已）无法自动发现。
2. 合成字不是真迹；严格字形请用 `GuanGeKai-C-Real.ttf`。
3. **简体码位的结构守衛**：抽 200 个简体码位，触发率 ep20 **17.0%**、ep40 **23.5%**
   （轮数增加没有降低触发率）。逐字看，触发的是**系统性偏旁繁体化**（纟→糹、鱼→魚、
   页→頁、钅→金），不是组件计数噪声；这些字回落到 ribbon，结构正确但笔形比 GAN 字平。繁体字不受影响。
4. `园`、`四` 的「囗」按写本风格开口（拓扑上无闭合孔），已从 C 线白名单移除并登记。
5. 生成字的字重现在与真迹一致（0.96–1.01），但**结构**仍来自模型，不是写本真迹。
