## 2. 质量闸（改为“先标定、越界进 suspect”）

### 2.1 WenKai 参照表（新增，必须落盘）

- 脚本：`scripts/99q_wenkai_ref_c.py`；
- 对 C 的每个唯一标签（~5–6k）渲染 WenKai 同字，按**同一协议**算：
  - `ink_density = mask_pixels / bbox_area`
  - `aspect = bbox_w / bbox_h`
- 输出 `work-c/wenkai_ref.json`：`{label: {density, aspect}}`；
- **无参照字**（WenKai 缺字）：写 `ref_missing`，不进硬闸，直接 `suspect_ref` 清单。

### 2.2 格子闸

| 闸 | 规则 | 越界 |
|---|---|---|
| ink_density 比 | `cell_density / ref_density` | 越界 → `suspect_fill`，**不丢弃** |
| aspect | 同字 WenKai aspect 的 0.5×–2.0× | 越界 → `suspect_shape_ref`，**不丢弃** |
| 横画白名单 | `一 二 三 丨 丶 丿 乙 亅` | 豁免 aspect 下限 |
| 硬兜底 | `fill < 0.04` 或 `min side < 0.30cp` | 空/碎片，丢弃 |
| 锚点 | 572 锚点 | **免检**，不参与闸 |

- 带宽 `[0.45,1.8]` **不再拍**；pilot 在全池 1,187,881 上算分位/IQR，写 `work-c/cluster/thresholds.json` 后生效；
- `thresholds.json` 必须含 `{n, 文件, 列, 过滤, 分位}`；pilot 20k 不作分位分母。

## 3. 聚类

- 48×48 向量，float16 memmap；`workers≤6`、`OMP/MKL=1`，`ps` 核对 ≤2000%；
- 10 万样本 PCA 64；
- **k-sweep 样本强制含 572 锚点**（100k 随机 + 全部锚点）；k∈{1k,2k,4k}；
- 选 k 判据：锚点冲突率 + 簇内熵，不用“每簇 50–100 格”；
- 全量 `MiniBatchKMeans(n_init=1, batch_size=10k)`，k 由 sweep 结果定，不写线性外推；
- 两阶段（2k→细分）备选；pilot 簇小（5–20 格），**验收指标不外推到全量**。

---

## 4. 簇输出与排序

四类：`suspect_mixed / suspect_shape / suspect_anchor / suspect_ref` + `clean_candidate`。

### 4.1 排序函数（必须写死）

sheet 顺序按：

```
① 锚点冲突（有锚点且不一致）
② 簇内标签熵（高→低）
③ OCR 代表分歧数（3–5）
④ 簇大小（大→小）
```

只出 top 1,000 簇 sheet；其余 suspect **保留原标签、清单落盘、不阻断 05**。

### 4.2 long-tail 语义

- 未人工看的 suspect：保留原标签，仅记录；
- 不进 `labeled_v2`，不改 chosen；
- 不因“没看”而丢弃。

### 4.3 clean_candidate

- 条件：A（现有标签多数）∧ C（锚点一致）∧ 代表 OCR 不冲突；
- 上限 = 572 锚点；无锚点永不入；
- 默认仍**不写 labeled_v2**；只作为候选清单。

## 9. 已知盲区

- 聚类对系统性错标失明（`一` 全错会高纯度）；靠锚点/人工，不靠纯度；
- A/B 同源，不独立；B 单独永不 high；
- 锚点只覆盖“盲审未标错”人群，缺陷人群零覆盖；
- clean_candidate 上限 572；
- 并格/空需 v3d3 几何修复；
- 空标签（12%）本轮不做“空→有”提候选，留 v4。

## 11. Pilot 实测结果（2026-10-30，20,580 格）

```bash
python3 scripts/99p_cluster_c.py --sample 20000 --clusters 300
# k-sweep: k=1000/2000/4000, 复用 emb.npz，--skip-ocr
```

| k | 中位簇大小 | purity 中位 | singleton | 锚点冲突（552 匹配） |
|---|---|---|---|---|
| 300 | 63 | 0.265 | 0 | — |
| 1,000 | 17 | 0.500 | 43 | **321 / 552 = 58.2%** |
| 2,000 | 7 | 0.711 | 306 | **281 / 552 = 50.9%** |
| 4,000 | 3 | 1.000 | 1,226 | **237 / 552 = 42.9%** |

- k=4,000 的 purity=1.0 是**碎片化假象**（1,226 个单格簇），不是可分；
- 代表 OCR 与簇 top 一致率 **36.4%**（k=300，899 次读数）；
- 锚点匹配 552/572，失败 20；锚点冲突率始终 **>42%**。

**结论：聚类不能作为标签真源或传播路径。**
- 高 purity 可以来自“单格簇”或“系统性错标同形”，不证明标签正确；
- 锚点冲突 43–58% 说明簇 top 与人工真值大面积不一致；
- 本 pilot **不进入全量聚类**；`99p`/`99q` 保留为诊断工具，不作为 v1.2.0 标签路径。

**下一步回到 v3d3 几何补丁 + 少量人工/锚点验证；聚类只在“找矛盾”时作为辅助清单，且不写 labeled_v2。**
